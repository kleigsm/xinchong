# 芯宠 · XinChong

> 把「专属外观、可变人格、桌面陪伴」三件事，合在一只桌宠上。

一款运行于 Windows 桌面的 AI 互动桌宠：**按规格导入图片与声音，组装出自己的专属桌宠；多套性格一键切换，点击或拖拽时以动作、表情和声音实时回应。**

产品刻意保持轻量——**不做聊天机器人，不做养成系统，不做功能堆砌**。定位是「轻量化桌面情感陪伴小伙伴」，核心价值聚焦「美化桌面」与「解压陪伴」。聊天是可选的增强项：用户自带 DeepSeek Key 才启用，没有就用固定话术。

> 📦 **本仓库 = 芯宠产品主体**：桌面客户端工程 + 产品/研究文档。
> 🌐 **门户网站**（介绍 + 下载页）在独立仓库：[kleigsm/xinchong-site](https://github.com/kleigsm/xinchong-site)

## 产品定位

| 维度 | 内容 |
|---|---|
| 一句话定位 | 轻量化桌面情感陪伴小伙伴 |
| 核心价值 | 美化桌面 · 解压陪伴 |
| 目标平台 | Windows（首版单平台验证） |
| 目标用户 | 18–22 岁在校大学生为主，女性占六成 |
| 产品理念 | 专属外观 × 可变人格 × 桌面陪伴，三合一 |
| 明确不做 | 聊天机器人 · 养成系统 · 功能堆砌 |

**产品边界的三条线**（来自用户研究，不是拍脑袋）：

1. **不做深度聊天**——两类用户都明确表示「要聊天会用专门的 App」，点击反馈就够。
2. **不做养成玩法**——问卷中仅 17.31% 想要养成，访谈中高兴趣用户明确排斥「吃饭洗澡那套」。
3. **不主动打扰**——默认静默、默认不主动搭话、开机自启默认关闭。

> 一个反直觉的结论：产品的默认值必须**优先服务审慎用户**（效率派），而不是声量更大的高兴趣用户。前者决定「会不会在一周内卸载」，后者只决定「会不会推荐」。

## 核心功能（MVP）

| 能力 | 说明 |
|---|---|
| 🖥️ **桌面悬浮** | 常驻桌面边缘，可点击、可拖拽、可一键临时隐藏 |
| 👆 **点击互动** | 点击/抚摸触发动作 + 简短台词 |
| 🎭 **多性格切换** | 开朗 / 傲娇 / 害羞，动作、台词、音效三件套差异化 |
| 🔕 **一键静音 / 勿扰** | 勿扰入口置顶，支持学习、会议状态识别 |
| 🖼️ **素材组装** | 用户导入立绘 / 表情差分 / 序列帧 / 录音，组装专属桌宠（Should） |
| 💬 **可选聊天** | 自带 DeepSeek Key 才启用，默认关闭；没有 Key 用固定话术（Could） |
| 🪟 **双通道运行** | 「全局桌面悬浮」与「仅窗口内运行」两种模式，首次启动即选 |

首版性格只做**害羞 + 开朗**（偏好 76.92% / 73.08%），傲娇次之（42.31%），高冷不做（1.92%）。

### 自定义的三级梯度

「专属」不等于「从零做动画」，按投入从小到大分三层：

| 级别 | 用户要做 | 耗时 | 能力 |
|---|---|---|---|
| **L1 选现成** | 挑预置角色，改名字 / 配色 / 性格 | 3 分钟 | 开箱即用 |
| **L2 换张脸** | 传 1 张立绘 + 可选表情差分，程序自动生成呼吸 / 眨眼 / 点击抖动 | 10 分钟 | 主流路径 |
| **L3 全自定义** | 按规格导入完整序列帧 + 录音 | 1 小时+ | 画师 / 硬核玩家 |

> 立绘和序列帧都支持，L2 是默认推荐路径。

## 为什么是现在：市场空白

竞品按竞争关系分三层看，只比其中一层都会失真：

| 层级 | 代表产品 | 强在哪 | 缺什么 |
|---|---|---|---|
| 桌宠直接竞品 | QQ 宠物（2026.7 手机端回归）、Shimeji、Desktop Goose | 陪伴互动足 | 个性化靠模板/皮肤，缺 AI 生成与人格 |
| AI 情感陪伴 | Character.AI（2026.10 申请破产保护）、星野、筑梦岛 | 人格对话成熟 | 无可见形象、无桌面驻留与动作/声音 |
| 形象生成上游 | Tripo、Meshy、即梦 | 生成能力最强 | 只是工具，无情感与陪伴 |

把竞品放进「情感陪伴深度 × 外观个性化」二维象限：

- 传统桌宠落在 **高情感 / 低个性化**
- AI 陪伴产品落在 **高情感 / 中等个性化**
- 生成工具落在 **高个性化 / 低情感**

**右上角「高情感陪伴 × 高外观个性化」目前没有产品占据**——这就是芯宠要站的位置。

三个能力组合构成错位竞争：用户导入自己的素材组装形象（把「选皮肤」升级为「有自己的角色」）、多性格切换（让陪伴有可变人格）、桌面实时动作与声音反馈（把互动从文本扩展到看得见摸得着）。

## 用户研究要点

**方法**：问卷 N=52（问卷星，95% 置信下抽样误差约 ±13.6%）+ 深度访谈 2 人（高兴趣 / 审慎两类各一）+ 竞品公开评价关键词核对。

**样本画像**：女性 61.54%，18–22 岁 61.54%，**Windows 电脑 90.38%**，全员日均使用电脑 ≥1 小时、近六成超过 3 小时。

**用户要的是什么**：

| 问题 | 关键数据 | 解读 |
|---|---|---|
| 期待桌宠带来什么 | 美化桌面 **92.31%**；解压 75%；聊天陪伴 46.15%；养成 17.31% | 「颜值 + 解压」是刚需，养成不是 |
| 现有 AI 陪伴的不满 | 性格不稳定 **55.77%**；缺动作声音 51.92%；无可视化形象 40.38% | 差异化不靠更强聊天，靠「性格稳定 + 看得见」 |
| 核心功能意愿（5 分制） | 点击动画 **4.35** > 多性格 4.04 > 上传图生成外观 3.71 | 先做「点了就有反应」 |
| 降低使用意愿的因素 | 卡顿 **73.08%**；形象不稳 **73.08%** | 性能与稳定是**红线**，不是加分项 |
| 使用意愿 | 50% 愿意主动下载，**0 人完全不想用** | 需求真实存在 |
| 商业模式接受度 | 基础免费 + 高级付费 63.46%；买断 28.85% | 免费增值 + 无广告买断版 |

**两类典型用户**：

| | 👧 用户 A「小甜心」 | 🧑‍💻 用户 B「效率派」 |
|---|---|---|
| 画像 | 女，20 岁，本科生，日均 3–6 小时 | 男，21 岁，理工科，日均 6 小时+ |
| 核心诉求 | 有专属形象、会按性格反应的陪伴者 | 低资源占用、低打扰，别来烦我 |
| 最不能缺 | 多性格、拖拽、一键静音、临时隐藏 | 低资源占用、可关闭全局悬浮 |
| 最排斥 | 复杂养成 | 多性格、声音、AI 生成（都属加分项） |
| 流失触发 | 连续 2–3 次生成崩坏 | 任何一次卡顿 / 遮挡 / 主动弹窗 |

**访谈挖出的隐性需求**：勿扰入口必须置顶；资源占用要在首屏可见；上传流程必须显式承诺「本地处理、用后即删」；需要「仅窗口内运行」选项。

## 需求优先级（MoSCoW）

### 功能性需求

| 编号 | 需求 | 优先级 |
|---|---|---|
| F1 | 桌面悬浮，可点击、拖拽、一键临时隐藏 | **Must** |
| F2 | 点击/抚摸触发动作 + 简短台词（不做长对话） | **Must** |
| F3 | 多性格切换，动作/台词/音效差异化 | **Must** |
| F4 | 一键静音 / 默认不主动搭话 / 勿扰模式 | **Must** |
| F5 | 素材组装：L1 预置角色 / L2 立绘+差分 / L3 序列帧+录音 | Should |
| F6 | 多形象收藏夹，快速切换 | Should |
| F7 | 「仅窗口内运行」或吸附边缘，不全局遮挡 | Should |
| F8 | 养成类小游戏（喂食、换装、升级） | Won't |
| F9 | 深度 AI 对话 / 角色扮演聊天（内置、默认开启） | Won't |
| F10 | 可选聊天：用户自带 DeepSeek Key，默认关闭，无 Key 回落固定话术 | Could |

### 非功能性需求

| 编号 | 需求 | 优先级 |
|---|---|---|
| N1 | 隐私：图片本地处理 / 用后即删 / 明确不上传云端 | **Must** |
| N2 | 性能：安装包小、内存占用低、卡顿自动暂停动画 | **Must** |
| N3 | 不打扰：默认不弹窗、默认静音、开机自启默认关闭 | **Must** |
| N4 | 生成质量稳定：畸形概率可控，连续失败 ≤2 次引导用默认形象 | Should |
| N5 | 跨窗口兼容：置顶不挡文档核心区 | Should |
| N6 | 轻量与启动速度：开机即可见，无冗长引导 | Could |

> **Must 项里没有任何一条是「提升对话能力」**——这条结论直接来自竞品分析：能力已经同质化，结构才是差异。

## 设计原则

1. **默认值服务审慎用户**：默认静默、默认不主动搭话、默认关闭开机自启、默认不上传图片。先取悦 B 类，再让 A 类自己「打开」丰富功能。
2. **双通道体验**：提供「全局桌面悬浮」与「仅窗口内运行」两种模式，首次启动即让用户选择。
3. **两条红线不可让步**：卡顿（73.08%）与形象不稳定（73.08%）。
4. **不押注生成算法**：形象来自用户提供的素材，程序负责「导入、校验、播放」；差异化押在「桌面交互」与「性格反馈」两层。
5. **风险兜底**：素材规格不合规 → 导入时校验并给出具体错误；桌面置顶兼容不确定 → Windows 单平台、窗口内运行先行验证。

## 多端策略

> **结论（2026-11 定）：桌面版优先；小程序延后，且只做「形象生成」这一类窄版本。**
> 记录在此，避免以后反复重新讨论「要不要加个小程序」。

### 为什么小程序不是「换个壳」

芯宠的差异化来自竞品分析的一条判断：大厂短期内不会做深的地方，是 **PC 桌面常驻 + 专属形象**。而微信小程序**做不到桌面悬浮**——它只能活在自己的窗口里，更接近 F7「仅窗口内运行」这条 Should 级通道。

把核心差异点拿掉之后，小程序只剩三种可能：

| 假设 | 小程序能做什么 | 与定位的关系 |
|---|---|---|
| **A. 素材组装器** | 手机上挑素材 / 拍照换色 → 组装形象 → 同步到桌面端 | 只覆盖 F5，是工具不是陪伴 |
| **B. 窗口内桌宠** | 小程序里养一只会动的宠物 | ❌ 丢掉「桌面常驻」，滑向聊天/养成（Won't） |
| **C. 素材云同步** | 管理云端形象库 | 依附桌面版，不能独立成立 |

**只做 A 类。** 手机端的素材挑选与组装体验优于 PC，而且它天然是官网的引流入口——「扫码组装你的专属形象，下载客户端领取」。小程序服务桌面版，不分走它。

### 阶段

| 阶段 | 做什么 | 前置条件 |
|---|---|---|
| **Phase 1（当前）** | 桌面端 F1–F4 跑通，拿到留存数据 | 无。在此之前**不开第二端** |
| **Phase 2** | 小程序 A 类：形象生成 + 一键到桌面端 | 桌面版有留存数据；类目审核通过 |

理由很直接：桌面端一行代码都还没有的时候就开第二战场，四个人最后两个都是半成品——这恰好违背报告里「严格控制 MVP 范围」的结论。

### 仓库规划

| 仓库 | 角色 | 状态 |
|---|---|---|
| `xinchong` | 产品主体：桌面客户端 + 产品/研究文档 | 进行中 |
| `xinchong-site` | 门户网站 | 已上线 |
| `xinchong-mp` | 微信小程序 | **暂不创建**，Phase 2 再建 |

**不用 monorepo**：小程序不能直接引用 `node_modules`，需要构建后拷贝，pnpm 的符号链接结构会和微信开发者工具的路径解析打架；为了共享几个类型定义引入 Taro / uni-app，对课程项目是纯负债。

共享靠**文档**不靠代码：性格设定、形象规范、台词表、接口约定放进 `docs/`，两端各自实现。

### 前置风险（优先级高于技术）

微信小程序对**生成式 AI** 与「虚拟陪伴」类目审核口径较严。**个人主体能否拿到「AI 形象生成」类目，必须先确认**——这个答案可能直接决定 A 类方案走不走得通，比怎么实现更重要。

## 客户端工程

> **当前状态**：客户端尚未进入实现阶段，仓库暂时只承载产品与研究文档。

### 技术选型（待定）

两条硬约束决定了选型：**N2 低内存**（73.08% 用户因卡顿弃用）与 **F1 桌面悬浮**（透明置顶窗 + 点击穿透）。

| 维度 | Electron | Tauri |
|---|---|---|
| 安装包体积 | ~80–150 MB | ~3–10 MB |
| 常驻内存 | 较高（自带 Chromium） | 较低（复用系统 WebView2） |
| 透明无边框窗 | 成熟 | 支持 |
| 点击穿透 | 成熟（`setIgnoreMouseEvents`） | 支持（`set_ignore_cursor_events`） |
| 置顶 | 成熟 | 支持 |
| 动画性能 | 稳定可控 | 依赖系统 WebView2 版本 |
| 生态与资料 | 最成熟 | 成长中，Rust 学习成本 |

**建议**：先用两者各做一个「透明置顶窗 + 点击穿透 + 拖拽」的最小验证，实测**空闲内存占用**后再定——这个数字直接对应产品的头号红线。

### 关键技术点

| 能力 | 实现要点 |
|---|---|
| 透明无边框窗 | 窗口背景透明，宠物以外区域完全不可见 |
| 点击穿透 | 透明区不拦截鼠标，仅角色区域响应点击 |
| 窗口置顶 | 始终置顶，但不遮挡文档核心区（N5） |
| 拖拽 | 按住角色拖动窗口，跨屏与 DPI 缩放要跟手 |
| 托盘与自启 | 托盘常驻，开机自启**默认关闭**（N3） |
| 双通道 | 「全局悬浮」/「仅窗口内」，首次启动让用户选 |
| 动画 | Lottie / Rive / 序列帧，按性格分包按需加载 |
| 图片处理 | 上传图本地换肤，**不上传云端**（N1） |
| 资源占用 | 内存/CPU 首屏可见，卡顿自动降帧 |

## 本地开发

```bash
pnpm install
pnpm dev        # 开发模式（热更新）
pnpm build      # 构建到 out/
pnpm start      # 运行构建产物
pnpm typecheck  # 类型检查
```

**两条硬性前置**：

1. **项目路径必须短且纯英文**（当前固定 `E:\xinchong`）。中文长路径会让 Electron 启动即崩，见 `docs/DECISIONS.md` D-404。
2. **清掉 `ELECTRON_RUN_AS_NODE`**，否则 Electron 会退化成 Node 模式、不开窗口：

```powershell
$env:ELECTRON_RUN_AS_NODE = $null
pnpm dev
```

## 发布与分发

客户端压缩包统一发布在**本仓库的 Releases**，门户网站只做跳转。

| 方案 | 评价 |
|---|---|
| **GitHub Releases** | ✅ 推荐。版本化、有下载量统计、不占仓库体积、免带宽费 |
| 塞进门户仓库 | ❌ 仓库体积膨胀，每次换包都要提交一次 |

发布流程：


## 合规提示

2026 年 7 月 15 日起施行的《人工智能拟人化互动服务管理暂行办法》明确：**不得向未成年人提供虚拟亲密关系服务**。

若产品包含「傲娇」「亲密」等人格表达，**首次启动必须完成年龄确认**，并在表达设定上划定边界。这一条在原型阶段就要落到流程里，不能等上线再补。
