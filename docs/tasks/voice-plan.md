# 声音计划（评审稿）

> 状态：**计划，未开工**。等排期与分工确定后再拆任务。
> 触发背景：评估 VoiceStudio 能否用于本项目的声音配置。

---

## 一、调研结论：VoiceStudio 怎么用

[VoiceStudio](https://voicestudio.sh/)（[GitHub](https://github.com/SimonTingle/voicestudio)）是**全本地运行**的开源 ElevenLabs 替代品：

| 能力 | 对我们有没有用 |
|---|---|
| 声音设计（文字描述 → 音色） | ✅ **有用**：三套性格可以直接生成三种音色 |
| TTS（文字 → 语音） | ✅ **有用**：把 174 条台词变成音频 |
| 声音克隆（3 秒样本） | ⚠️ 有用但**合规风险高**，见阶段 3 |
| 本地 HTTP API | ❌ 不用：我们要零运行时依赖 |
| 多引擎切换 | 🟡 架构可参考，暂不实现 |

### 核心判断

> **VoiceStudio 对我们最有价值的是「制作端」，不是「运行端」。**
>
> 它是生产工具（把文字变成音频资产），不是运行时依赖（在桌宠里跑 TTS 模型）。

### 为什么不在客户端跑 TTS

| 原因 | 数据 |
|---|---|
| **体积** | TTS 模型几百 MB ~ 几 GB；我们全包才 136 MB |
| **延迟** | 本地推理 300ms–2s；我们的气泡是瞬间出现的 |
| **内存** | 本地推理要几 GB；我们当前 442 MB |
| **维护** | 多一套 Python/ONNX 运行时 |

| 项 | 数值 |
|---|---|
| 台词 | **174 条纯文本**（3 套 × 58 条 × 10 场景），只显示在气泡里，**不出声** |

### 阶段 1：台词发声（P2-8）—— **最推荐先做**

**目标**：点击时气泡出现的同时，播放这句话的语音。

**做法**：离线预生成，运行时只播文件。

```
开发机（一次性）：
  174 条台词 × 3 套性格
    → VoiceStudio「声音设计」生成 3 个音色
    → 批量合成 → 转 opus/mp3 64kbps
    → 写入 src/renderer/assets/voice/<性格>/

运行时：
  气泡出现 → 同时播 <hash>.ogg
  文件不存在 → 静默（不回落 TTS）
```

**文件命名**：用**文本哈希**而不是数组下标——

```
voice/shy/3f2a91c4.ogg     ← sha1(台词文本)[:8]
voice/shy/manifest.json    ← { "3f2a91c4": "……诶？", ... }
```

理由：以后改台词顺序、增删条目都不会错位。

**体积估算**：

| 项 | 数值 |
|---|---|
| 条数 | 174 |
| 平均时长 | 1.5–2 秒 |
| 总时长 | 约 5 分钟 |
| opus 64kbps | **约 2.5 MB** |

**验收**：
- [ ] 点击后 50ms 内出声（本地文件，无延迟）
- [ ] 三套性格音色能明显区分
- [ ] 静音 / 勿扰下不出声
- [ ] 包体增加 ≤ 4 MB
- [ ] **空闲 CPU 不上升**（播放是一次性的，不是循环）
- [ ] 缺失音频时静默，不报错

### 阶段 2：声音资产化（P2-9）—— **有合规闸，押后**

**目标**：声音像角色一样，可以打包 / 导入 / 分享。

| 子项 | 说明 |
|---|---|
| 声音包格式 | `voice-pack.json` + 若干音频，声明 id / 名称 / 音色 / 授权 |
| 内置 4 套 | 现有语音包升级成正式的声音包 |
| 用户导入 | 用户自己提供音频（**不是**克隆他人） |

**⚠️ 合规闸（必须先过再开工）**：

| 风险 | 处理 |
|---|---|
| 克隆真人声音 | **不做**。只允许用户导入自己的录音，且需勾选"我拥有该声音的使用权" |
| 未成年人 | 沿用现有合规口径，不做亲密向表达 |
| 模型许可 | 若用 XTTS 类模型生成内置音色，需确认模型许可（多数为**非商用**），并在 README 声明 |

### 阶段 3（可选）：实时 TTS

只有在前两个阶段验证"用户确实想要它说话"之后才考虑。

| 方案 | 体积 | 延迟 | 离线 |
|---|---|---|---|
| Piper（轻量本地） | ~50 MB | 200–500ms | ✅ |
| Edge TTS | 0 | 300ms+ | ❌ 联网，违背隐私承诺 |
| Windows SAPI | 0 | 快 | ✅（音质差） |

## 五、决策点（需要拍板）

| # | 问题 | 我的建议 |
|---|---|---|
| 1 | 台词要不要**全部**发声？ | **部分发声**：点击/摸头/招手发声；睡觉/久未互动**不发声**（避免吵） |
| 2 | 三套性格音色用"声音设计"还是"角色配音"？ | 先试生成 10 条对比，再定 |
| 3 | 用户能否导入自己的声音？ | 技术上可以，但要过合规闸；**建议先不做** |
| 4 | 用的 TTS 模型许可是否允许？ | 必须确认；非商用也要在 README 写明 |

## 六、明确不做

| 不做 | 原因 |
|---|---|
| 客户端内置 TTS 模型 | 体积/延迟/内存三重代价 |
| 克隆真人声音（家人/朋友/偶像） | 声音权 + 深度伪造风险 |
| 运行时调用云端 TTS | 违背"图片与数据不上传"的隐私承诺 |
| 让每句都用 AI 实时生成 | 台词是固定的 174 条，预生成即可 |
