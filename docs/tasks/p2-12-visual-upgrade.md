# 任务书 · P2-12 视觉升级（桌宠感）

**负责人**：林予炫
**估时**：3 天（分两步，第二步可裁剪）
**性质**：代码为主，少量美术协作（眨眼差分图可选）
**状态**：⬜ 待开始

---

## 一、为什么做（问题陈述）

用户/老师反馈：**界面"太原始"，不像桌宠，像一个网页小工具**。

拆开看，具体是这五件事：

| # | 现象 | 根因 |
|---|---|---|
| 1 | 角色像"翻页书"，站那儿不动 | 雪碧图 8–12 fps 循环，没有微动效（呼吸以外没有别的） |
| 2 | 角色和桌面贴在一起，没有"存在感" | 没有软阴影 / 接地阴影 / 边缘柔化 / 环境光 |
| 3 | 拖起来像搬一张图 | 纯位移，没有惯性、摆荡、松手回弹 |
| 4 | 点一下只有气泡和表情切换 | 反馈层次少（没有粒子/闪光/轻微镜头感） |
| 5 | 设置面板是普通 HTML 卡片 | 过渡生硬、间距/层级与角色不在一个视觉语言里 |

> 注意：这不是"再加功能"，是**把已有功能做得有生命感**——和产品定位（美化桌面、解压陪伴）直接相关。

---

## 二、工具与方案对比

按「投入 / 风险 / 收益」排序，**A → B → C** 是递进关系，不是三选一。

| 方案 | 用什么 | 能解决 | 成本 | 风险 |
|---|---|---|---|---|
| **A. 轻量增强（本次必做）** | 纯 CSS + TS（可选 GSAP 做缓动） | 1 / 2 / 3 / 4 / 5 中的大部分 | 1.5–2d | 低：不动渲染管线，随时可回退 |
| **B. WebGL 渲染 + 滤镜（POC）** | PixiJS + pixi-filters | 发光 / 描边 / 投影 / 色调，仍用现有雪碧图 | 1–2d | 中：换渲染层，**必须复测空闲 CPU/GPU** |
| **C. 骨骼动画（另立项）** | Spine（`@esotericsoftware/spine-player`）或 Live2D（`pixi-live2d-display` + Cubism Core） | 头发/尾巴物理、看向、真实动作 | 3–5d + 美术出模型 | 高：美术成本 + 授权（Spine 商用需 license；Live2D 有营收门槛） |
| D. 状态机动画（备选） | Rive（`@rive-app/canvas`） | 交互驱动的状态切换，运行时小 | 3d + 美术 | 中：同样要美术重做模型 |
| E. 窗口材质（可选点缀） | `mica-electron` / `electron-acrylic-window` | 设置窗亚克力/云母背景 | 0.5d | 中：透明窗兼容性与性能未验证 |

**明确不建议**：

- 引入 React/Vue 重写设置面板 —— 收益是"更现代"，但会把 8 个页面全部重写，风险远大于收益（现有设计 token 已经够用）
- 引入 matter-js 物理引擎 —— 只有"一个角色"，手写弹簧就够了，别为 20 行逻辑加 100KB 依赖

## 三、本次范围（推荐路线）

### Step 1 · 轻量增强（必做，1.5d）

| 项 | 做法 | 验收观感 |
|---|---|---|
| 待机呼吸 | 已有（L2/L3），保留 | 轻微起伏 |
| **眨眼** | 优先用美术差分图（闭眼帧）叠 100ms；没有差分图时用 `scaleY` 压缩模拟 | 30 秒内至少眨 1 次 |
| **视线跟随** | 监听全局光标，按方向给角色一个 ≤6px 的偏移（只动 `transform`，节流到 ~15fps） | 鼠标在附近移动时角色"看你" |
| **拖拽惯性** | 记录速度，松手后按速度做 0.15–0.3s 衰减 + 轻微倾斜 | 不再"硬停" |
| **落地回弹** | 松手后 `translateY` 过冲再回位（弹簧曲线） | 有"踩地"感 |
| **软阴影** | 角色底部椭圆阴影，随离地高度缩放/变淡 | 有"贴地"感，不像贴纸 |
| **点击反馈** | 复用现有 `fx.ts`，加 1 层轻量粒子（爱心/星星），≤300ms | 点击更有回应 |
| **设置面板过渡** | 页面切换加 120–160ms 淡入/位移；卡片 hover 微抬 | 不再"唰"地切换 |

⚠️ **性能红线**（P2-4 已经踩过的坑）：`filter: drop-shadow` 在**每帧 transform** 的元素上会强制重栅格化，空闲 CPU 从 5% 涨到 40%+。
所以阴影要么放**另一个元素**上（不参与每帧 transform），要么用预渲染的 PNG 阴影。

### Step 2 · PixiJS 滤镜 POC（可选，1d）

- 用 PixiJS 播**现有雪碧图**（不改素材），加 `glow` / `outline` / `dropShadow` 滤镜
- 必须记录：空闲 CPU、GPU、内存、启动耗时，达标（CPU ≤ 6%）才替换
- 不达标就保留 Step 1 的 CSS 方案，写进日志说明原因

### 不做（边界）

- ❌ 不改角色素材规格（继续支持 4/5/9 行雪碧图 + 单张立绘）
- ❌ 不引入前端框架（React/Vue/Svelte）重写设置面板
- ❌ 不引入联网运行时资源（CDN 字体/图片）
- ❌ 不碰 `hit-test.ts` / `window.ts` 的命中与窗口逻辑（P1-11 的地盘），如必须改先与高晟铭对齐

## 四、验收标准

**观感（录屏或截图对比"改前/改后"）**

- [ ] 待机 30 秒：能看出呼吸 + 眨眼 + 轻微摇摆，不像静态图
- [ ] 鼠标在角色附近移动：视线跟随自然，不抖动、不延迟感明显
- [ ] 拖拽：松手有回弹/惯性和轻微倾斜，不是硬停
- [ ] 角色脚下有软阴影，拖起时阴影变小变淡
- [ ] 点击有粒子/闪光反馈，且不遮挡角色超过 300ms
- [ ] 设置面板切页有过渡，hover 有反馈

**性能（红线，必须实测并写进日志）**

- [ ] L3 雪碧图空闲 CPU **≤ 6%**（现状 5.89%）
- [ ] L2 单图空闲 CPU **≤ 5.5%**（现状 5.16%）
- [ ] 启动耗时 ≤ 0.6s（现状 0.44/0.56）
- [ ] 打包体积增量 ≤ 300KB（不引大依赖）

**工程**

- [ ] `pnpm typecheck` / `pnpm test` / `pnpm build` 全过
- [ ] 静音 / 勿扰行为不变（勿扰时不冒台词、不出声，动画照常）
- [ ] 不破坏既有交互：点击 / 双击 / 长按 / 连点三下 / 拖拽 / 快捷面板
