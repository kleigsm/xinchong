## 三、演示脚本要包含什么

**目标**：3 分钟内让评委看到"这是个什么东西"和"它为什么值得做"。

### 建议结构（共 180 秒）

| 时间 | 段落 | 内容 |
|---|---|---|
| 0:00–0:20 | 开场 | 一句话说清是什么 + 直接让桌宠出现 |
| 0:20–1:10 | 核心交互 | 单击说话 → 双击招手 → 长按摸头 → 拖拽 |
| 1:10–1:40 | 三套性格 | 切换性格，展示形象/台词/音色都变 |
| 1:40–2:10 | 差异化 | **导入自己的角色**（一张图 → 自动动画） |
| 2:10–2:40 | 设计依据 | 说清哪些功能来自调研（卡顿红线、遮挡红线、隐私） |
| 2:40–3:00 | 收尾 | 打开官网，展示下载按钮 |

### 每条要写清楚

- **画面**：屏幕上出现什么（含具体坐标/操作）
- **操作**：演示者做什么（点哪里、按什么键）
- **口播**：同时说什么
- **注意点**：这一步容易出什么岔子（比如"托盘图标可能被折叠"）

## 四、PPT 大纲要包含什么

每页给出：**标题 + 3–4 个要点 + 配图建议**。

建议结构：

| 页 | 标题 | 要点 |
|---|---|---|
| 1 | 封面 | 项目名、团队、课程 |
| 2 | 问题 | 为什么做桌宠？现有产品的三个问题（卡顿/遮挡/同质化） |
| 3 | 用户研究 | 问卷 N=52 + 访谈 2 人的关键结论 |
| 4 | 产品定位 | 一句话 + 两条红线 |
| 5 | 功能地图 | F1–F10 的优先级划分（Must/Should/Won't） |
| 6 | 核心体验 | 8 个动作 + 台词引擎（截图） |
| 7 | **技术难点** | 透明窗穿透 / DPI 拖拽 / 性能（用实测数据） |
| 8 | **性能数据** | 5.89% CPU、442MB、启动 0.44s（对比图） |
| 9 | 差异化 | 导入自己的角色（L2/L3 两条路径） |
| 10 | 隐私设计 | 本地处理、Key 加密、BYO-Key |
| 11 | 迭代过程 | 从 0 到 v0.1.0 的分阶段推进（可放 PR 数量） |
| 12 | 反思与展望 | 做对了什么、没做好什么、下一步 |

## 五、可以用的事实与数据

**用户研究**（来自项目 README）：

- 问卷 N=52
- 73.08% 用户因**卡顿**弃用
- 90.38% 用 Windows
- 53.85% 首要顾虑是**隐私**（图片不外传）

**技术数据**（来自 `docs/perf-baseline.md`）：

| 指标 | 数值 |
|---|---|
| 启动耗时 | 0.44 s（开发）/ 0.56 s（打包） |
| 空闲 CPU | 5.89%（雪碧图）/ 5.16%（单图） |
| 内存 | 442 MB |
| 安装包 | 136.5 MB |
| 帧率优化 | 从 60fps CSS 动画（42.7% CPU）降到 8fps JS（5.16%） |

**工程数据**：

- 41 个 PR（#1 → #41）
- 三套角色各 36 帧
- 10 个台词场景
- 从零到发布约 5 天
