# 任务书 · P3-3 用户测试

**负责人**：朱哲弘
**估时**：2 天（含约人）
**性质**：**不用写代码，主要是找人和观察**

---

## 一、要做什么

找 **5 个人**，让他们自己下载、自己安装、自己玩，你在旁边**看和记**。

注意：**你不是去教他们用的，是去看他们会不会用。**

---

## 二、为什么这件事重要

我们开发了半个月，已经不知道"第一次用的人"会怎么理解它了。

我们以为的：

> 打开就能看到桌宠，点一下有反应，右键有菜单

真实的新用户可能会：

> 打开后什么都没看见（托盘图标被折叠了）
> 桌面上一块透明的区域，不知道能不能点
> 点了一下，它说了句话，然后就不知道还能干嘛

**这些我们永远猜不到，只能看真人用。**

---

## 三、怎么做（三步）

### 第 1 步：找人（5 个）

要求：

- 用过电脑就行，不需要懂技术
- **最好有一个是"不喜欢桌宠"的人**（这类人的反馈最有价值）
- 至少一个用笔记本（可能涉及缩放比例）

### 第 2 步：让他们自己装（关键）

把官网链接发给他，然后**闭嘴看着**：

```
https://xinchong-site.onrender.com
```

**你什么都不要说，也不要帮他点。** 只记三件事：

- 他第一眼看到了什么
- 他卡在哪一步
- 他在哪一步犹豫了超过 3 秒

> 如果他自己找到了下载按钮、解压、双击运行，说明我们的引导是够的。
> 如果他卡住了，那就是我们页面/引导的问题——**这本身就是结论**。

### 第 3 步：玩 2 分钟，然后问三个问题

**别看屏幕的时候问，等他玩完再问**：

1. 刚才有没有哪里卡住了？
2. 有没有什么地方你没看懂？
3. 有没有觉得烦、想关掉的地方？

然后追问一句：

> 如果现在让你跟别人介绍这个东西，你会怎么说？

**这一句能看出他到底理解成什么了**——如果他说"一个会说话的小人"，说明我们想传达的"陪伴感"没传达到。

---

## 四、要记录什么

新建 `docs/testing/user-feedback.md`，每个用户一段：

```markdown
## 用户 1

**环境**：Windows 11 / 125% 缩放 / 单屏 / 笔记本

**安装过程**
- 找到下载按钮用时：约 20 秒
- 卡住的地方：解压后不知道点哪个文件（里面有很多文件）
- 总耗时：约 3 分钟

**第一反应**
- 原话：「哦，是个小机器人」

**玩的过程**
- 点了 3 下，看到台词
- 没发现双击/长按（**没有看设置里的「怎么玩」**）
- 右键菜单是自己试出来的

**三个问题的回答**
1. 卡住：安装那步
2. 没看懂：不知道还能干嘛
3. 觉得烦：没有，但说「有点幼稚」（原话）

**介绍时会怎么说**
- 「一个桌面上会动的小东西，点它会有反应」

**问题分级**
- P1：安装包里文件太多，不知道点哪个（解压后应只有一个 exe 或加个说明）
- P2：新用户不知道有双击/长按这些交互

```

### 问题分级标准

| 级别 | 含义 | 例子 |
|---|---|---|
| **P0** | 装不上 / 打不开 / 崩溃 | 双击没反应、报错 |
| **P1** | 能跑但被卡住，任务没完成 | 找不到下载、解压不知道点哪个 |
| **P2** | 能用但体验差 / 没发现功能 | 没注意到右键菜单、觉得太大 |

## 六、验收

- [ ] 至少 5 个用户，每人一段完整记录

```markdown
1. ...
2. ...
3. ...
```

## 八、最容易犯的错（提前说）

| 错误 | 后果 |
|---|---|
| **边看边教他** | 测出来的是"你教得好"，不是"产品好" |
| 只找懂电脑的人 | 反馈会偏乐观 |
| 只记"好的地方" | 那不用测了 |
| 用户卡住时帮他操作 | **他卡住的那一刻才是最有价值的** |
| 问"你觉得怎么样" | 得到的都是客套话。要问**具体行为**：卡在哪、犹豫了多久 |
