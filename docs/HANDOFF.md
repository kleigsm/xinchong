# 多会话协作指南（交接模板）

> 这份文档是给**人**看的：当你把项目拆成多个对话窗口并行推进时，怎么让每个新窗口"无缝接手"。
> AI 接手的入口是 [`AGENTS.md`](../AGENTS.md)，两者配合使用。

---

## 为什么需要这个

一个对话的上下文是有限的。项目做大之后，常见做法是：

- **主窗口**：统筹、决策、排期、跨任务排查
- **子窗口**：各自负责一个具体任务（如"打包"、"设置面板"、"台词表"）

多窗口之间**唯一的共享记忆是仓库里的文件**。所以：

> 聊天记录不算产出，**写进文件才算**。

---

## 三条原则

### ① 第一句只说"去哪儿读"，不说"是什么"

新窗口的上下文是空的，但仓库不是。不要粘贴几百行背景，给它四个路径就够了。

### ② 一个窗口只做一个任务

多个任务混在一个对话里，最后分不清哪句话属于哪个任务。

### ③ 结论必须落盘

子窗口聊出来的方案，不写进 `docs/`，主窗口就永远不知道。

## 通用开场模板

```text
项目：芯宠，Windows 桌面桌宠。
仓库：E:\xinchong（工作区必须设成这个目录）

请按顺序读，读完再动手：
1. AGENTS.md —— 接管须知与硬约束
2. docs/STATUS.md —— 当前进度
3. docs/BACKLOG.md —— 找到下面这个任务的验收标准
4. docs/log/ 里最近 2 篇

本次任务：<任务号> <任务名>

要求：
- 遵守 AGENTS.md 的分支 / PR / 更新日志规矩
- 不改与本任务无关的文件
- 先用自己的话复述：当前项目做到哪、这个任务要交付什么、你打算怎么做
- 我确认后再开始写代码
```

**最后那条"先复述"很重要**：既是验证（证明真读了文档），也是纠偏（理解错了当场改，比写完再改便宜十倍）。

## 三种常见变体

### 做功能

```text
本次任务：P1-8 设置面板
验收标准见 docs/BACKLOG.md。做完要能：改音量、改性格、看内存占用。
```

### 修 bug

```text
现象：<具体现象，越具体越好>
复现步骤：<1. 2. 3.>
期望：<应该怎样>
先查 docs/log/ 里有没有相关记录，再动手。
```

### 写文档 / 素材

```text
本次任务：C1 三套性格台词表
参考 docs/specs/asset-spec.md 第 3 节的台词要求（条数、字数）。
产出写成 docs/specs/lines/<性格>.md，不要只留在对话里。
```

## 子窗口收尾（必说）

```text
结束前请把结论写进仓库：
- 更新 docs/STATUS.md
- 新增 docs/log/<日期>-<任务号>.md
- 有决策就写进 docs/DECISIONS.md
- 提交并开 PR
```

**没有这一步，这个子窗口的工作对主窗口等于不存在。**

---

## 主窗口怎么配合

开子窗口之前，在主窗口说：

> 「我要开个子窗口做 P3-1，帮我把任务说明和当前相关状态整理成一段可以直接粘贴的话」

主窗口会读最新状态，给你一段贴合当下的开场（含当前进度、相关文件、已知坑）。

子窗口完成后，在主窗口说：

> 「P3-1 做完了，PR #XX 已合并」

主窗口读 `docs/log/` 和 `git log` 就能接上，不需要复述细节。

## 故障排查

| 现象 | 原因 | 解决 |
|---|---|---|
| 新窗口说"不知道项目在哪" | 工作区没设成 `E:\xinchong` | 重新打开工作区，`AGENTS.md` 才会被加载 |
| 新窗口改了无关文件 | 没读 BACKLOG 的验收标准 | 开场模板里的"不改无关文件"要保留 |
| 子窗口的结论主窗口看不到 | 没写进 `docs/` | 收尾模板必须执行 |
| 两个窗口改了同一个文件冲突 | 任务没拆开 | 一个窗口一个任务；改同一文件前先 pull |

---

## 任务拆分建议

按 `docs/BACKLOG.md` 的编号走，一个编号 = 一个窗口：

- 有依赖关系的任务**不要并行**（如 P1-1 和 P1-2）
- 互不依赖的可以并行（如 C1 台词表 和 P3-1 打包）
- 同一线内尽量串行，避免同一文件反复冲突
