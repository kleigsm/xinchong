# 技术架构

> 用一句话概括：**桌宠 = 一个"透明、置顶、可点击穿透"的窗口 + 里面循环播放的动画 + 一个决定"现在播什么"的状态机。**

---

## 一、先看三个开源项目，各学一件事

| 项目 | 是什么 | 我们能学什么 |
|---|---|---|
| [BongoCat](https://github.com/ayangweb/BongoCat) | Electron 系的桌面猫，Live2D 模型，眼睛跟着鼠标动，按键有反应 | **验证了整套形态可行**：透明窗口 + 模型 + 事件驱动，离线不联网。它的「自带模型」思路正好对应我们的「换肤」 |
| [Shimeji](https://github.com/topics/shimeji-ee) | 经典的 Java 桌宠，精灵图 + 行为定义 | **行为状态机**的鼻祖。它证明「动画 + 状态 + 配置」三件套足够做出一只活物，不需要 AI |
| [DSHpet](https://github.com/lxtCuSO4/DSHpet) | 支持自定义角色的桌宠，透明动画、点击拖拽、多宠物 | **配置化素材**的做法：角色、动作、参数都写成配置，程序只负责播 |

三者的共同点：**没有一个是"靠 AI 聊天"撑起来的**，全都靠「动画 + 反馈」制造生命感。这和我们调研的结论完全一致（用户要的是「好看 + 解压」，不是「能聊」）。

## 二、进程模型

Electron 天生分两个进程，正好对应「身体」和「大脑」：

```
┌──────────────────────────────────────────────┐
│  主进程（Node.js，没有界面）                   │
│  · 创建/移动窗口                              │
│  · 托盘图标与右键菜单                          │
│  · 开机自启（写注册表）                         │
│  · 读写设置文件                                │
│  · 单实例锁（防止开两只）                       │
└──────────────────┬───────────────────────────┘
                   │  IPC（只通过 preload 暴露的白名单方法）
┌──────────────────┴───────────────────────────┐
│  渲染进程（一个透明的网页）                     │
│  · 宠物动画播放（Canvas / Live2D / 精灵图）     │
│  · 状态机（待机 / 点击 / 拖拽 / 睡觉）          │
│  · 台词气泡                                    │
│  · 音效播放                                    │
└──────────────────────────────────────────────┘
```

**为什么要分？**
窗口能不能置顶、能不能穿透、托盘怎么画——这些是操作系统的事，只能主进程干。
动画怎么动、台词说什么——这些是画面的事，在渲染进程里干最快。
两边用 IPC 通信，**渲染进程不碰 Node**（安全底线）。

## 三、技术选型

| 层 | 选什么 | 为什么 | 备选 |
|---|---|---|---|
| 桌面壳 | **Electron** | 纯 JS/TS，团队不用学 Rust；透明窗 + 点击穿透 API 成熟且被 BongoCat 验证过 | Tauri（包小但需 Rust） |
| 语言 | **TypeScript** | 四个人协作，类型能挡住大量低级错误 | JavaScript |
| 构建 | **electron-vite** | 主进程和渲染进程都能热更新，模板开箱即用 | 手写 Vite + electron-builder |
| 界面框架 | **无框架**（原生 DOM） | 桌宠只有一个画面，不需要路由和组件库，引入 React/Vue 是负担 | Vue 3 |
| 动画 | **精灵图（PNG 序列帧）起步**，后续可换 Live2D | 序列帧零依赖、最可控；Live2D 效果好但需要模型和 SDK | Lottie / Rive |
| 状态管理 | **自写状态机**（switch + 定时器） | 只有 4 个状态，引入 XState 是过度设计 | XState |
| 本地存储 | **electron-store** | 一个 JSON 文件搞定设置、形象列表 | 自己写 fs |
| 图片处理 | **sharp**（主进程）或 Canvas | 本地裁剪、调色、缩放 | jimp（纯 JS，免编译） |
| 素材校验 | **sharp 读元数据** + 自定义规则 | 尺寸、透明通道、命名、缺帧都能查 | — |
| 音频 | **HTMLAudioElement** | 短音效足够 | howler.js |
| 密钥存储 | **Electron `safeStorage`** | 系统级加密，明文不落盘 | keytar |
| 聊天请求 | **主进程 `fetch`**（Node 内置） | Key 不进渲染进程；DeepSeek 兼容 OpenAI 格式 | axios |
| 打包 | **electron-builder** | 生态最成熟，出绿色版 zip 最简单 | electron-forge |

## 五、桌宠是怎么"活"起来的

### 1. 动画 = 翻页书

一组 PNG，按顺序快速播放就是动画：

```
idle_0.png → idle_1.png → idle_2.png → idle_1.png → （循环）
```

每秒 12–24 张。播放器只做一件事：**定时换图**。

### 2. 状态机 = "我现在该干嘛"

```
        点击
待机 ──────────> 点击反应 ──(播完)──> 待机
 │                                    ▲
 │ 30 秒没互动                          │
 ▼                                    │
睡觉 ────────────(被点醒)─────────────┘
```

规则只有几条：

- 待机时，隔一会儿随机播一个小动作（眨眼、晃尾）
- 被点击，播「点击反应」，播完回待机
- 被拖拽时，切到「被拎起来」的姿势
- 久未互动进入睡觉

**实现就是一个 `switch (currentState)` + 切换时的清理定时器。** 不需要框架。

### 3. 性格 = 一份配置表

加一种性格，**不改代码，只加一个配置**：

```ts
// src/shared/personalities/shy.ts
export const shy = {
  name: "害羞",
  animations: {
    idle: "shy/idle_%d.png",
    click: "shy/blush_%d.png",
    drag: "shy/fluster_%d.png",
  },
  lines: {
    click: ["……诶？", "别、别突然戳我啦", "（脸红）"],
    drag: ["要掉下去了……！"],
    idleLong: ["……你在忙吗"],
  },
  sounds: {
    click: "shy/ehh.mp3",
  },
};
```

切性格 = 换一个配置对象。动作、台词、音效**同时**跟着变，这正是问卷里 55.77% 用户抱怨「性格不稳定」的解药。

## 六、素材管线（这是主线，不是边角料）

**芯宠不是「AI 生成形象」，而是「用户按规格提供素材 → 程序组装成一只活的桌宠」。** 所以素材管线是核心功能，不是附属工具。

### 6.1 用户的素材从哪来（三级梯度）

| 级别 | 用户提供 | 程序负责 | 耗时 |
|---|---|---|---|
| **L1 选现成** | 什么都不用给 | 预置角色 + 改名字/配色/性格 | 3 分钟 |
| **L2 换张脸** | 1 张立绘（+ 可选 2–4 张表情差分） | 自动裁边、统一尺寸、**合成呼吸/眨眼/抖动动画** | 10 分钟 |
| **L3 全自定义** | 完整序列帧 + 录音 | 校验、按命名规则装配、播放 | 1 小时+ |

L2 是默认推荐路径，也是决定产品成败的一层——它把「专属」的门槛从「会做动画」降到「有一张图」。

### 6.2 素材规格（这是给用户的契约）

| 素材 | 格式 | 规格 | L2 | L3 |
|---|---|---|---|---|
| 立绘 | PNG 透明背景 | 建议 512×512，正面朝前，四周留 10% 余量 | 必需 | 可选 |
| 表情差分 | PNG 透明背景 | 与立绘同尺寸、同位置 | 可选 | 可选 |
| 动作序列帧 | PNG 序列 | `动作_序号.png`，如 `click_01.png`，12fps | — | 必需 |
| 声音 | mp3 / wav | ≤ 3 秒，命名与动作对应 | 可选 | 可选 |
| 性格 | 选预置或自定义台词 | 决定台词库、动作映射、语气 | 必需 | 必需 |

配套交付物：

1. **素材包模板 zip** —— 用户下载后照着填，目录结构和命名都摆好
2. **校验器** —— 见下
3. **实时预览** —— 导入后立刻能看，不用重启

### 6.3 导入流程

```
选择素材（文件/文件夹/压缩包）
        ↓
校验（尺寸、透明通道、命名、缺帧）
        ↓
   ┌────┴────┐
 通过        不通过
   ↓           ↓
生成预览    列出具体问题
   ↓        （"click_03.png 缺失，
应用          点击动画只有 2 帧"）
```

**校验器的错误提示必须说人话**。写「格式错误」用户就走了；写「立绘不是透明背景，请在导出时勾选透明」才有用。

### 6.4 一张静态图怎么「活」起来（L2 的核心技巧）

不用做真动画，用变换伪造：

| 效果 | 做法 | 成本 |
|---|---|---|
| 呼吸 | 整体缩放 ±1.5%，周期 3 秒 | GPU 合成，几乎零 CPU |
| 眨眼 | 叠加表情差分 100ms | 一次换图 |
| 点击抖动 | 位移 + 旋转 ±3°，150ms | GPU 合成 |
| 被拖拽 | 倾斜 10° + 轻微缩放 | GPU 合成 |

这些全是 CSS transform，**不重绘、不耗 CPU**，正是性能红线（73.08%）的解法。

## 七、聊天模块（可选，默认关闭）

### 7.1 定位

**聊天不是主线，是增强项。** 产品默认只有固定话术；用户主动填了自己的 DeepSeek Key，才升级成真对话。这样既不违背「不做聊天机器人」的定位，又给想要的人留了口子。

### 7.2 两条路径

```
用户填了 Key 吗？
├── 没有 → 本地话术库（JSON，按性格 + 场景挑句子）
│           永远可用，零成本，零延迟
└── 有   → 主进程调 DeepSeek API
            成功 → 显示回复
            失败 → 回落本地话术库，并提示一次（不反复弹）
```

### 7.3 安全与隐私

| 事项 | 做法 |
|---|---|
| Key 存哪 | 用 Electron `safeStorage` 加密后存在本地，**明文不落盘** |
| 谁发请求 | **主进程**发；渲染进程拿不到 Key（只通过 IPC 请求"帮我问一句"） |
| 上传什么 | 只上传用户输入的文本 + 性格设定；**不上传图片、音频、截图** |
| 首次启用 | 弹窗说明「对话内容会发送到 DeepSeek」，用户确认后才生效 |
| 卸载 | 提供「清除 Key」按钮 |

### 7.4 Prompt 怎么拼

```
system: 你是「{宠物名}」，性格是{害羞/开朗/傲娇}。
        说话简短，不超过两句话。
        {性格专属的语气描述与禁忌}
user:   {用户说的话}
```

上下文只带最近 3–5 轮，避免 token 膨胀。

### 7.5 降级策略

| 情况 | 表现 |
|---|---|
| 没填 Key | 静默使用固定话术，不提示 |
| Key 无效 / 401 | 提示「Key 似乎不对」，自动回落固定话术 |
| 网络失败 / 超时 5s | 回落固定话术，本轮不重试 |
| 额度用尽 | 提示一次，之后静默回落 |

**原则：任何情况下宠物都不能"哑掉"。**

## 八、五个一定会踩的坑

| 坑 | 现象 | 解法 |
|---|---|---|
| **透明窗口和点击穿透自相矛盾** | 全窗穿透后，宠物也点不到了 | 鼠标位置轮询：进入角色包围盒时关穿透，离开时开回来 |
| **用 CSS 拖拽会吞掉点击** | `-webkit-app-region: drag` 让点击事件全部失效 | 自己实现拖拽：`mousedown` 记偏移 → `mousemove` 调 `setPosition` |
| **置顶窗口抢焦点** | 一点宠物，你的代码编辑器就失焦 | `focusable: false` + `skipTaskbar: true` |
| **多显示器和缩放漂移** | 笔记本接了显示器后，宠物跑到屏幕外 | 用 `screen.getDisplayMatching` 换算坐标，别写死像素 |
| **打包后资源找不到** | dev 能跑，装完就白屏 | 路径统一走 `app.getAppPath()`，别用相对路径 |
| **中文长路径直接崩** | 启动即退出，`0x80000003`，没有任何报错 | 项目路径保持短且纯英文，当前固定 `E:\xinchong`（见 D-404） |
| **preload 暴露名撞了全局变量** | 窗口正常显示、点击毫无反应，控制台里其实早报错 | `exposeInMainWorld("pet")` 后，渲染层不能再用 `const pet`；并务必把 `console-message` 转发到主进程 |

这七条每一条都能让人卡一整天。**建议 P0-3 就把前三个验掉。**

| 周 | 做什么 | 能看到的成果 |

## 十、为什么不用别的方案

| 方案 | 为什么不选 |
|---|---|
| Tauri | 要 Rust；WebView2 版本差异会让动画表现不可控。作为备选保留，见 `DECISIONS.md` D-004 |
| Unity / Godot | 做桌宠要自己处理透明窗、点击穿透、托盘，等于重造轮子；包体也大 |
| 纯 Win32 / WPF | 只有 Windows，团队学习成本高，且动画生态弱 |
| 网页 + 插件 | 做不到真正的桌面常驻 |
