# 每次开工 / 收工流程

> 目标：**不重复劳动、不越界、不把工作区弄乱。**
> 每次开工按 0→3 走，收工前必须过第 4 节。

---

## 0. 开工检查（5 分钟）

### 0.1 先查上游，再决定要不要同步

```powershell
# 1) 最新 main
curl.exe -sSL https://api.github.com/repos/kleigsm/xinchong/commits/main

# 2) 和上次记录的 main 对比
curl.exe -sSL "https://api.github.com/repos/kleigsm/xinchong/compare/<上次sha>...<最新sha>"

# 3) 看有没有新 PR
curl.exe -sSL "https://api.github.com/repos/kleigsm/xinchong/pulls?state=open"
```

判断：

- **无新提交**：直接用当前工作区
- **有新提交**：
  - 先读 `docs/STATUS.md`、新 `docs/log/`，看别人改了什么
  - 只把相关文件同步进来，**不要整目录覆盖**
  - 同步后重新跑 `pnpm typecheck && pnpm test`
- **有冲突/不确定**：先停在开工检查，不要写代码

### 0.2 读项目状态

按 `AGENTS.md` 顺序：

1. `docs/STATUS.md`
2. `docs/BACKLOG.md`
3. `docs/log/` 最近 3 篇
4. `docs/DECISIONS.md`

### 0.3 盘点工作区

- 有没有上次留下的临时文件、截图、`.pr-work`、`.sync`、`__pycache__`
- 有没有没提交的本地改动
- 当前跑的是 `C:\xc` 还是打包版？版本是否一致
- 记下这次收工要清理什么

### 0.4 写开工三行

```md
- 日期：
- 上游 main：<sha>（有无新提交）
- 本次目标：<一句话>
- 明确不做：<边界>
```

---

## 1. 想法 → 方案（先选，再开工）

任何想法先过四道闸，**不要直接写代码**。

### 1.1 产品定位闸

| 问题 | 通过条件 |
|---|---|
| 是否让桌宠更“活”？ | 外观 / 动作 / 声音 / 性格反馈 |
| 是否变成聊天机器人？ | 否 |
| 是否加养成/等级/任务？ | 否 |
| 是否主动打扰用户？ | 否 |
| 是否要上传图片到云端？ | 否；必须本地或明确 opt-in |
| 是否明显增加卡顿/包体？ | 不能碰红线 |

### 1.2 分工闸

| 线 | 范围 | 我们做什么 |
|---|---|---|
| C 美术与内容 | 角色、台词、音效、模板、演示素材、规格 | 主导 |
| B 交互与动画 | 窗口、状态机、运行时、设置页、播放器 | 只出规格/素材，不抢代码 |
| D 产品与质量 | 测试、验收、用户反馈 | 配合 |

**不是自己线的：写成任务书/接口说明，交出去，不顺手改。**

### 1.3 方案对比闸

至少列 2 个方案：

| 方案 | 成本 | 风险 | 可逆性 | 结论 |
|---|---|---|---|---|
| A | | | | |
| B | | | | |

选**最小可验证**的那个；大功能先 POC，不直接铺开。

### 1.4 验收闸

开工前写清：

- 完成标准（可测）
- 不做什么（non-goals）
- 怎么验（命令/步骤/截图）
- 谁来验（C/B/D）

四道闸都过了，才建分支。

---

## 2. 执行

- 一个任务 = 一个分支 = 一个 PR
- 分支名：`feat/<任务号>-<短描述>` / `fix/<bug号>-<短描述>`
- 小步提交，提交信息中文一句话
- C 线交付必须带：源文件 + 预览 + 许可/来源 + 校验结果
- B 线交付必须带：接口、验收清单、性能数据
- 中途发现越界或新问题：先记 `docs/testing/issues.md`，不要顺手扩 scope

---

## 3. 自测（提交前）

```powershell
pnpm typecheck
pnpm test
pnpm build
```

- 三种运行方式按需验证：`pnpm dev` / `pnpm start` / 打包 exe
- UI/素材改动必须实机看/听，不能只看代码
- 性能敏感改动记录 CPU/内存/帧率

---

## 4. 收工（10 分钟，必须做）

### 4.1 文档

- [ ] `docs/STATUS.md` 更新
- [ ] 新增 `docs/log/YYYY-MM-DD-<任务号>.md`
- [ ] 新问题写进 `docs/testing/issues.md`
- [ ] PR 描述写清“做了什么/怎么验/不做什么”

### 4.2 PR 状态

- [ ] 分支已推送
- [ ] PR 已创建（或记录 compare 链接和阻塞原因）
- [ ] 没有把临时文件、模型、安装包提交进去

### 4.3 工作区清理

按 `workspace-cleanup` 原则：

**保留**

- `src/`、`docs/`、`resources/`、`art/`、脚本与配置
- `交付/`（最终素材）
- `测试素材/`（用户原始资料/测试图）
- `.tools/`（本地工具，不进 git）

**清理**

- 根目录临时截图：`screen.png`、`*.tmp.png`
- 一次性脚本：`gen_*.py`、`fix_*.py`、`try_*.py`
- 临时克隆：`.pr-work/`、`.sync/`（PR 已创建/合并后）
- 缓存：`__pycache__/`、`*.pyc`
- 构建中间物：`out/`、`dist/`（需要时再构建）
- 下载的压缩包、模型（除非还要继续用）

**检查**

```powershell
# 根目录不该有临时文件
Get-ChildItem -Force | Where-Object { $_.Name -match '\.(png|py|zip|7z)$|^gen_|^fix_|^try_' }

# 不能有 node_modules / 安装包
Get-ChildItem -Recurse -Directory -Filter node_modules -ErrorAction SilentlyContinue
```

### 4.4 收工记录

```md
- 本次完成：
- 未完成/阻塞：
- 下次第一件事：
- 工作区已清理：是/否
```

---

## 5. 红线速查

| 不要做 | 原因 |
|---|---|
| 没查上游就改 | 容易和已合并的 PR 冲突 |
| 想法直接写代码 | 越界/返工 |
| 顺手改 B 线代码 | 分工混乱 |
| 把 AI 模型/大素材塞进安装包 | 包体/隐私红线 |
| 收工不清理 | 下次开工先花时间找文件 |
| 把第三方角色图提交公开仓库 | 版权风险 |
