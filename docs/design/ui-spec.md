# 芯宠 · 交互设计规范 v1

> 2026-11-09 ｜ 对应原型：[`prototype/index.html`](prototype/index.html)（可交互，见 [README](README.md)）
> 本规范覆盖三件事：**长按浮球**、**右键菜单改版**、**贴边收纳**。落地任务建议编号 P1-11。

---

## 一、设计目标

| 目标 | 现状问题 | 本条设计怎么解 |
|---|---|---|
| **可发现性** | 12 项功能全藏在右键里，新用户不知道能干啥（STATUS 第九节已记录） | 长按 2 秒出 4 个浮球，把最高频的入口摆在眼前 |
| **信息架构** | 右键菜单一列 12 项，无分组、无图标 | 分三组（常用 / 安静 / 系统）+ 图标 + 快捷键提示 |
| **不挡事** | 桌宠永远浮在桌面右下角，看视频时挡字幕 | 拖到屏幕边缘自动收一半，悬停滑出 |

**贯穿原则**：不新增任何"常驻可见"的 UI。浮球只在长按后出现，5 秒无操作自动收回。

---

## 二、三个入口的分工

| 入口 | 面向 | 内容 | 保留理由 |
|---|---|---|---|
| **长按浮球** | 新用户 / 高频操作 | 说句话、换性格、静音、设置 | 解决"不知道有右键" |
| **右键菜单** | 熟练用户 / 完整功能 | 全部 12 项，分组呈现 | Windows 肌肉记忆，不能砍 |
| **托盘菜单** | 找不回桌宠时 | 与右键菜单一致（同一份 `buildMenu`） | 托盘图标是兜底入口 |

> 浮球是**快捷方式**，不是替代。右键菜单只做信息架构优化，不删功能。

## 三、长按手势时序

```
按下 ──0.0s─────────────────────────────────────────────
      │
      ├─1.2s─→ 摸头：播 0.67s 动画 + 气泡「（被摸头，脸红了）」
      │        此时松手 = 只摸头，不出菜单
      │
      └─2.0s─→ 浮球展开（120ms 缩放淡入）
               此时松手 = 菜单保持打开
```

| 参数 | 值 | 说明 |
|---|---|---|
| 摸头触发 | 1200 ms | 沿用现有实现，不改 |
| 菜单触发 | 2000 ms | 摸头动画（0.67s）刚好播完，不打架 |
| 拖拽判定 | 位移 > 4 px | 与现有一致；一旦判定拖拽，取消两个定时器 |
| 展开动画 | 120 ms `cubic-bezier(0.2,0.9,0.3,1.2)` | 只动 `transform` / `opacity` |
| 自动收回 | 5000 ms | 无操作自动关，防"忘了关" |
| 收起方式 | 点球 / 点角色本体 / 点设置窗 / Esc | 点桌面空白处不收起（那里是穿透区，收不到事件） |

## 四、浮球几何

窗口坐标（320×340，角色圆心 `(160, 262)`）：

| 球 | 动作 | 圆心 | 极坐标 |
|---|---|---|---|
| 说句话 | 打开聊天输入条 | (75, 202) | r=104, 145° |
| 换性格 | 害羞 → 开朗 → 傲娇 | (128, 163) | r=104, 108° |
| 静音 | 切换静音 | (192, 163) | r=104, 72° |
| 设置 | 打开设置窗口 | (245, 202) | r=104, 35° |

| 尺寸项 | 值 |
|---|---|
| 球直径 | 44 px |
| 图标字号 | 17 px |
| 标签字号 / 位置 | 10 px，球上方 46 px |
| 环半径 | 104 px（自角色圆心） |
| 球间距（相邻圆心角） | 36–37° |
| 触达半径（命中） | 22 + 6 = 28 px |

**为什么是上半圆而不是整圈**：窗口只有 320×340，角色贴底；下半圆会被窗口边界裁掉。上半圆能看到 4 个球且不遮挡角色脸。

**第 5 个球（勿扰）**：若加，半径拉到 112，角度 160°/120°/90°/60°/20°，球径缩到 40。当前 v1 不加，留待实测。

## 五、命中区域（这是本设计最容易翻车的地方）

窗口默认**整窗穿透**，只有光标落在「交互区域」内才切换为可点。2026-11-08 的聊天输入框 bug 就是因为输入条不在命中区域里（`docs/log/2026-11-08-chat-input-clickthrough.md`）。

### 5.1 区域定义

| 区域 | 形状 | 参数 |
|---|---|---|
| 角色 | 圆 | 圆心 (160, 262)，r = 82 |
| 聊天输入条 | 矩形 | x 20–300，y 122–171（打开时） |
| 浮球 × 4 | 圆 | 各自圆心，r = 28（菜单打开时） |

### 5.2 实现建议

渲染层在状态变化时把「当前交互区域」推给主进程（新增 IPC `interactive-regions`），`hit-test.ts` 求并集判断：

```ts
type Region =
  | { kind: "circle"; x: number; y: number; r: number }
  | { kind: "rect"; x: number; y: number; w: number; h: number };
```

**不要**再在 `hit-test.ts` 里逐个写死 if —— 每加一个 UI 元素都要改一次命中逻辑，输入条的 bug 就是这么来的。

### 5.3 验收
- 光标移到任一浮球上 → 日志 `ignore=false`
- 光标移开浮球（回到空白） → `ignore=true`
- 菜单打开时，点击空白区域仍能穿透到后面的窗口

## 六、右键菜单改版

| 组 | 项 | 图标 | 快捷键 |
|---|---|---|---|
| **常用** | 说句话… | 💬 | — |
| | 换性格 ▸ | 🎭 | — |
| | 我的角色 ▸ | 🧸 | — |
| **安静** | 静音 | 🔕 | — |
| | 勿扰模式 | 🌙 | — |
| | 音量 ▸ | 🔊 | — |
| **系统** | 设置… | ⚙ | Ctrl+, |
| | 性能信息 | 📊 | — |
| | 退出芯宠 | 👋 | — |

**去掉的**：「显示 / 隐藏」「动作 ▸」「开机自启」。
- 显示/隐藏 → 托盘已有，且菜单里点它等于"点了就看不见菜单"，反直觉。
- 动作 → 收进设置或浮球（低频）。
- 开机自启 → 设置页已有开关。

> 若担心功能"消失"，可在「设置 → 行为」里补一行入口说明；不建议在菜单里保留。

## 七、贴边收纳

| 项 | 值 |
|---|---|
| 触发 | 拖拽松手时，窗口与屏幕边缘距离 < 24 px |
| 收起状态 | 向该侧平移 168 px（只露 152 px） |
| 展开 | 鼠标进入窗口任意位置，滑出 72 px（保留 96 px 在外） |
| 动画 | 260 ms `cubic-bezier(0.2,0.8,0.2,1)` |
| 取消收纳 | 拖离边缘 > 24 px |

**注意**：收纳时窗口仍占 320×340 的透明区域，命中检测要用"收纳后的可见矩形"，否则鼠标滑出会闪烁。

## 八、状态互斥

| 状态 | 可同时存在 | 必须关闭 |
|---|---|---|
| 浮球展开 | 静音 / 勿扰 / 贴边 | 聊天输入条、右键菜单 |
| 聊天输入条 | 静音 / 勿扰 | 浮球、右键菜单 |
| 右键菜单 | 静音 / 勿扰 | 浮球、聊天输入条 |
| 贴边 | 任意 | — |

**同一时刻只能有一个"面板"**。打开新面板时关闭旧的（原型里已验证）。

---

## 九、性能约束（硬指标）

| 约束 | 值 | 依据 |
|---|---|---|
| 浮球展开/收起 | 只允许 `transform` + `opacity` | 透明窗口每帧合成成本高 |
| **禁止** `filter` / `backdrop-filter` / `box-shadow` 动画 | — | perf-baseline 第八节：`drop-shadow` 让 CPU 从 6% → 42.7% |
| 静止时零动画 | 浮球展开后不再动 | 空闲 CPU 已有 5.89% 预算 |
| 菜单打开时空闲 CPU | < 8% | 与 2× 速度同一条红线 |
| 空闲（菜单关闭） | 不增加任何定时器 | — |

**静态阴影可以用**（`box-shadow` 固定值不参与动画），它不触发每帧重新栅格化。

## 十、可访问性

| 项 | 做法 |
|---|---|
| 键盘 | Esc 收起所有面板；`Ctrl+,` 打开设置 |
| 读屏 | 每个球 `aria-label="说句话"`；菜单项保持原生语义 |
| 减少动画 | 尊重 `prefers-reduced-motion`：展开动画降为 0 ms |
| 误触保护 | 球与球之间留 8 px 空隙（44 球 + 36° 间隔） |
