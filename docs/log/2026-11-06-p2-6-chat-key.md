# 2026-11-06 · P2-6 聊天地基：Key 安全存储

## 目标

聊天功能的第一刀：**让用户能安全地填自己的 DeepSeek Key**。
真正的对话调用等 P2-5 话术引擎合并后再接（失败要能回落到台词库）。

## 两条硬要求

1. **绝不明文落盘**——Key 是用户的钱，泄露了要负责任
2. **不放进 `settings.json`**——那个文件是给用户看、容易被截图发出去的

## 方案

```
%APPDATA%\xinchong\chat-key.bin    ← 加密后的二进制，独立于 settings.json
```

加密用 Electron 的 `safeStorage`：

| 平台 | 底层 | 效果 |
|---|---|---|
| Windows | DPAPI | 密文只能被**当前 Windows 账户**解开 |
| macOS | Keychain | 同上 |
| Linux | libsecret | 同上 |

也就是说：把 `chat-key.bin` 拷到别的电脑、或换个 Windows 账户登录，都解不开。

## 完成内容

### 1. `src/main/chat-key.ts`

| 函数 | 作用 |
|---|---|
| `saveChatKey(key)` | 校验非空 → `safeStorage.encryptString` → 写文件 |
| `loadChatKey()` | 读文件 → 解密；失败返回 null（比如换了账户） |
| `clearChatKey()` | 删除文件 |
| `maskChatKey(key)` | 显示成 `sk-…cdef`，供界面确认"填的是哪把" |
| `isEncryptionAvailable()` | 系统加密是否可用（不可用时要明确告诉用户） |

### 3. 「测试连接」真的打了一次 API

```
POST https://api.deepseek.com/chat/completions
{ model: "deepseek-chat", messages: [...], max_tokens: 4 }
```

状态码映射成人话：

| 返回 | 提示 |
|---|---|
| 200 | 连接正常，Key 可用 |
| 401 | Key 无效或已过期 |
| 402 | 账户余额不足 |
| 429 | 请求太频繁 |
| 超时 | 连接超时，检查网络或代理 |
