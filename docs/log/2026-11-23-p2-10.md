# 2026-11-23 · P2-10 对话上下文本地存档 + 按形象隔离

## 背景：三个 bug

`chat.ts` 原来把上下文放在一个全局 `history` 数组里：

| 问题 | 表现 |
|---|---|
| 跨形象串味 | 跟害羞聊完切傲娇，傲娇知道害羞说过的「我叫小明」 |
| 重启失忆 | 只在内存，关掉全忘 |
| 记性太短 | 只带 3 问 3 答，聊 5 轮接不上 |
| 死代码 | `resetChatHistory()` 定义了但没人调用 |

不是新功能，是修 bug。

## 设计

### 存档结构（`%APPDATA%\xinchong\chats.json`）

```json
{
  "version": 1,
  "characters": {
    "builtin:shy": { "updatedAt": 1735000000000, "turns": [{ "role": "user", "content": "在吗", "at": 1735000001000 }] },
    "custom:cat-01": { "updatedAt": 0, "turns": [] }
  }
}
```

- **键**：`builtin:<性格>` / `custom:<petId>`，切角色直接换 key，天然不串味
- **保留**：最近 20 轮（40 条消息）
- **发送**：最近 6 轮（12 条），token 可控
- **写入**：每轮结束 500ms 防抖；退出前 `before-quit` flush
- **原子写**：先写 `.tmp` 再 `rename`，避免崩溃留下半个 JSON

### 分层

| 文件 | 职责 |
|---|---|
| `src/shared/chat-archive.ts`（新） | **纯逻辑**：解析 / 校验 / 裁剪 / 拼上下文。不碰 fs 和 Electron，全部可单测 |
| `src/main/chat-store.ts`（新） | 读写、缓存、防抖、备份损坏文件 |

把纯逻辑和 IO 拆开，是为了让「文件坏了怎么办」这类分支能被单测覆盖，而不是靠手测。

### 容错

- JSON 坏了 / 结构不对 / 版本不认识 → **备份**成 `chats.json.<时间>.bak`，然后按空历史继续跑
- 单个角色结构坏了只丢它，其余角色保留（`recovered: true` 会触发备份）
- 空文件 / 只有空白 → 当空存档，不算损坏

### 没验证的

**真实 API 往返（聊 3 轮 → 重启 → 还记得）没跑**：要用用户的真实 Key 发请求（花钱）。
用单测覆盖了中间最关键的一环——请求体里的 `messages` 是否是这个角色的上下文、成功后是否写回同一个 key。
真机往返留给你或验收时点两下即可。

## 两个自行决定的细节

1. **内置三套性格常驻列表**（没有记录也显示「暂无记录」），这样清空入口稳定存在；自定义角色只在有记录时出现。
2. **「清空所有」= 删文件**，不是写一个空对象——和隐私页「删掉」的语义一致。
