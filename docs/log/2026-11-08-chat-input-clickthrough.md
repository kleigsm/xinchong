# 2026-11-08 · 修 bug：聊天输入条点不动、打不了字

## 现象

右键桌宠 →「说句话…」→ 输入条出现在头顶，但**点不进去，也打不了字**。
（输入条有时候是已经聚焦的，能盲打；但只要用鼠标去点它，就彻底没反应。）

## 原因：点击穿透把输入框吃掉了

桌宠窗口是整窗透明的，靠 `hit-test.ts` 每 80ms 轮询光标位置，判断"在不在角色身上"，
不在就 `setIgnoreMouseEvents(true)` —— 整窗穿透，点击漏到后面的窗口。

但聊天输入条（`#chat-box`）画在角色**上方**：

| 元素 | 窗口内位置（CSS px） |
|---|---|
| `#chat-box` | y 126–174，宽 280 居中 |
| `#pet` | y 182–342（160×160） |

命中圆只覆盖 y 180–344（圆心在角色底部，半径 82）。
**输入条整个落在命中区域外面**，于是光标一挪到输入框上，窗口立刻变穿透：
点不到输入框、IME 也拿不到焦点 —— 用户看到的就是"点了没用"。

这也解释了为什么"盲打"有时候能成：窗口刚打开时 `openChatInput` 抢到了键盘焦点，
但鼠标一碰输入框，穿透开关就把窗口从手底下抽走了。

## 改法

1. `chat-input.ts` 记一个 `chatOpen` 状态，并导出 `isChatInputOpen()`；
   打开时立刻 `setIgnoreMouseEvents(false)`，不等 80ms 轮询。
2. `hit-test.ts` 在输入条打开期间，除角色命中圆外**额外放行输入条那块矩形**
   （矩形参数按实测值放进 `shared/constants.ts`，带 6px 余量）。
3. 关闭输入条后状态复位，窗口恢复"只在角色身上可点"。

只放行输入条矩形，而不是整窗可点：否则输入条打开的那几秒里，
整个 320×340 的透明区域都会挡住后面的窗口，反而更烦。

## 验证（125% 缩放，物理坐标）

| 步骤 | 结果 |
|---|---|
| 右键 →「说句话…」 | ✅ 输入条出现，`document.hasFocus() = true` |
| 鼠标移到输入框上 | ✅ 日志 `[hit] cursor on pet → ignore=false`（修复前是 `ignore=true`） |
| 点输入框 | ✅ 边框变粉（`:focus`），光标在框内 |
| 输入拼音 | ✅ IME 候选窗正常，上屏「你」 |
| 移开鼠标 | ✅ 恢复 `ignore=true`，点到后面的窗口正常 |
| `pnpm typecheck` / `build` | ✅ |

## 踩坑补充

- `document.hasFocus()` 是判断"窗口到底有没有键盘焦点"最快的手段；
  只看 `document.activeElement` 会骗人——DOM 焦点在，但窗口没激活，键盘事件照样进不来。
- 排查时用 CDP 连渲染进程读 `hasFocus / activeElement / chatHidden`，
  比截图猜快得多。
