# 2026-11-03 · P0-1 技术选型 spike（进行中）

## 目标

开出一个 200×200 的透明置顶窗，验证「透明 + 点击穿透 + 可点击」三者能否共存，并拿到内存 / CPU 数字。

## 已完成

- 工程初始化：`package.json`、`main.js`、`preload.js`、`renderer.js`、`index.html`
- Electron 版本：**33.4.11**（原因见下）
- 窗口参数：`transparent` / `frame:false` / `alwaysOnTop` / `skipTaskbar` / `focusable:false`
- 穿透逻辑：整窗默认穿透（`setIgnoreMouseEvents(true, {forward:true})`），鼠标进入角色范围时关闭穿透
- 拖拽逻辑：自己算偏移 + `setPosition`，**没有用** `-webkit-app-region: drag`
- 附加：呼吸动画（纯 transform）、hover 检测、日志打点
- 测量脚本：`scripts/measure.ps1`（进程数 / 内存 / 空闲 CPU）

## 遇到的问题

**1. Electron 二进制下载极慢**

- 45.2.1 的 158MB 包，国内镜像只有 ~65KB/s，需 40 分钟
- 处理：改用本机缓存里已有的 **33.4.11**（205MB，`%LOCALAPPDATA%\electron\Cache`），秒装
- 影响：版本落后于原计划的 45.2.1。**API 无差异**（透明窗与穿透都是老 API），但正式工程 P0-2 时要决定是否升级

**2. `ELECTRON_RUN_AS_NODE=1` 环境变量**

- 该变量存在时，Electron 会退化成 Node 模式，**不开窗口**
- 处理：启动前必须清掉

**3. 当前执行环境禁止启动 GUI 程序**

- 实测：`electron.exe` 与 `notepad.exe` 都无法启动（退出码 `0x80000003` / `0xC0000005`）
- 结论：**AI 侧无法验证窗口效果，必须由人在桌面上运行**
