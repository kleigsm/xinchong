# 2026-11-23 · P2-11 自定义音效包导入

## 背景

音效主题原来只有 5 个（跟随性格 + 狗/猫/鸟/猪）。`docs/specs/sounds/custom-sound-integration.md` 早就写好了「用户导入自己的音效包」的格式，但**没有导入入口、没有设置项**。

这次把它落地：用户可以拿自己的狗叫/猫叫/环境音替换点击、拖拽、睡眠等音效。

## 格式（按规格）

```
my-dog-sounds/
├── manifest.json
├── click-1.ogg
└── ...
```

```json
{ "id": "my-dog-sounds", "name": "我的小狗", "version": 1, "license": "CC0",
  "sounds": { "click": ["click-1.ogg"], "drag": ["drag-1.ogg"],
              "sleep": ["sleep-1.ogg"], "appear": ["appear-1.ogg"], "confirm": ["confirm-1.ogg"] } }
```

校验规则：id 小写字母/数字/短横线；必需 5 种（appear/click/drag/sleep/confirm）；
单个文件 ≤2MB、总包 ≤20MB、每个音频 ≤2 秒；路径必须是包目录根下的相对文件名（禁 `..`、绝对路径、子目录）。

## 设计

### 两阶段导入：静态校验在主进程，时长校验在渲染层

```
选文件夹 → 主进程：读 manifest、查文件存在/大小、复制到 .staging-<token>、返回 data URL
        → 渲染层：Web Audio 解码，超过 2 秒就拒绝 → 取消（删 staging）
        → 主进程：rename staging → sounds/<id>，写 settings.soundTheme = "user:<id>"
```

为什么时长不主进程做：那要给主进程引入音频解码依赖（music-metadata 之类）。
渲染层本来就跑在 Chromium 里，`decodeAudioData` 是现成的——不引依赖，规则还更准。

失败时 staging 一律删掉，不会留下半成品。

### 播放链路

`SoundPlayer` 增加用户包分支：

- 切到 `user:<id>` → 通过 IPC 拿文件清单，**预加载 5 种常用音效**，再把 data URL 缓存起来
- 播放时文件名随机取（支持多变体）；文件没加载完先静默一帧，避免和内置音叠加
- 包被删/读不出来 → 回落「跟随性格」→ 再回落合成音

### CSP

`<audio src="data:...">` 需要 `media-src data:`，两个页面的 CSP 都加了。

## 踩到的坑

| 坑 | 现象 | 解决 |
|---|---|---|
| preload 丢了参数 | `soundImport(dir)` 走到预加载变无参，弹了原生对话框卡住 | preload 显式透传参数 |
| `fetch(dataUrl)` 被 CSP 拦 | 设置页 `TypeError: Failed to fetch` | 改用 `atob` 手动解码，不用 fetch（也不加 connect-src） |
| `Uint8Array.buffer` 类型 | TS 报 `ArrayBufferLike` 不能赋给 `ArrayBuffer` | `dataUrlBytes` 直接返回 `ArrayBuffer` |

## 验证（开发版实机）

| 项 | 结果 |
|---|---|
| 导入合法包（5 个 wav） | ✅ 解码时长 0.15–0.3s，commit 成功，`soundTheme=user:my-pack` |
| 主题切换 | ✅ 设置页出现「我的音效包」并选中；桌宠点一下日志 `[audio] play click (user=my-pack)` |

| 缺文件 | ✅ 「找不到音频文件：click-1.wav」 |

| typecheck / test / build | ✅ 71 个单测（新增 12 个 manifest/路径/大小） |

## 没做 / 下一步

- **zip 导入**：这版只支持文件夹（规格允许二者之一）。zip 要解压库或自己写 zip 解析，留到需要时
- **试听只放 5 种必需音效**（不是全部 9 种）
- 音效包目录不参与隐私页清点（属于用户数据，但还没纳入「对话记录/角色」那套清单）
- 打包版验证：只跑了开发版，打包后 `userData/sounds` 路径一致，应该没问题，发版前再点一遍

## 追加：修「音效主题点了没反应」（BUG-023）

**用户反馈**：动物的音效主题用不了。

排查下来不是播放的问题——按主题名直接调 `patchSettings` 再点桌宠，四套动物音效都能正常加载并播放（实测 dog/cat/bird/pig 四个包都 `play()` 成功）。

真正的原因是**设置页的选择器根本没接线**：

| 项 | 内容 |
|---|---|
| 按钮 | `data-action="segment-text"`（C2 交付时写的） |
| 点击处理 | 只处理 `action === "segment"` |
| 结果 | 点任何主题都不发 `patchSettings`，主题永远是「跟随性格」 |

修复：

1. 主题按钮改用 `data-action="segment"`（和外观/行为页的控件一致）
2. 切主题后调 `soundTrial()`，让桌宠用当前主题**试播一声**，用户不用再去点桌宠确认

验证：点「猫咪」→ `soundTheme=cat`、按钮高亮切过去、桌宠日志 `[audio] play click (pack=cat)`；导入用户包后点它 → `[audio] play click (user=my-pack)`。
