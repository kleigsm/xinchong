# 2026-11-22 · 修拖拽偏移 + 松手后继续跟随

## 现象（用户实测）

1. 拖动桌宠时有**偏移**：宠物不跟着光标走，总觉得"超前/落后一截"。
2. 鼠标停下/松手后，宠物**还在动**，有继续跟着光标的趋势。

## 根因

### 1. 偏移：锚点取晚了

渲染层原来是在**第一次 mousemove**（位移 > 4px）时才通知主进程开始拖拽：

```
mousedown ──(鼠标已移动 20px)──> 第一次 mousemove ──> dragStart
                                                      ↑
                                     主进程这时才用"当前位置"算偏移
```

主进程算偏移用的是「此刻光标 − 窗口位置」，可此刻光标已经比按下时多走了 20px，
这 20px 被永久算进锚点 → 宠物永远比光标滞后 20px。

实测（旧版）：按住后把光标移 (−240,−140)，窗口只动 (−220,−120)，差 20px，
且停住 1 秒也不回补。

### 2. 松手后还在动：drag-end 丢了

主进程的拖拽循环（每 16ms 跟一次光标）**只靠渲染层的 `drag-end` 停止**。
快速拖动时光标会先离开角色命中圆，`hit-test` 把窗口切回穿透 →
窗口收不到 `mouseup` → `drag-end` 永远不来 → 循环一直跑，宠物继续跟着光标走。

## 改法

| 改动 | 说明 |
|---|---|
| `mousedown` 立刻 `dragStart` | 锚点用**按下那一刻**的位置（`event.screenX/Y`），起步那段不会被算成偏移 |
| `ipc.ts` 的 `drag-start` 用传入的 `point` | 原来忽略参数、改用此刻光标位置——正是偏移的来源 |
| 松手一律 `dragEnd` | 点击、摸头、拖拽三条路径都收尾，不再依赖 `dragging` 标志 |
| 窗口 `blur` 兜底 `endDrag` | 拖到一半切窗口也不会留下循环 |
| 输入框内按下不启动拖拽 | 免得在输入框点一下也起拖拽循环 |

|---|---|

| 相对距离稳定 | ✅ 8 次采样，光标−窗口恒定 (200,325)，无漂移 |
| 停住不动 | ✅ 窗口位置不变 |

## 遗留

- 拖拽循环仍是 16ms 轮询系统光标；如果将来上高刷屏想要更跟手，可以改成 8ms（代价是 CPU）
- 拖到屏幕边缘时窗口会被 `clampPosition` 夹住，此时光标继续外移、宠物不动，属预期

## v1.2（松手后仍有"继续运动"的手感）

用户反馈"结束的时候还有继续运动"，量化后发现两个残留问题：

### 1. 松手时停不到光标位置

16ms 的定时器可能还停在上一帧，`drag-end` 一到循环就停了，宠物**差几十像素没跟上**。
实测：光标甩到 DIP(920,480)、锚点偏移 (160,260)，理论上窗口应到 (760,220)，
实际停在更靠后的位置——看起来就是"松手了还在往回追 / 总差一截"。

**改法**：`drag-end` 时按**当前光标**补算一次目标位置再夹紧，保证落点精确。
实测同样操作：窗口落在 (760,220)，和理论值一致。

### 2. 采样间隔 16ms 偏慢

快速拖动时宠物最多落后 1–2 帧，视觉上就是"发飘、停了还在滑"。
按住期间把轮询从 16ms 收紧到 **8ms**（只在按住期间跑，CPU 可忽略）。
实测甩动后松手：光标 DIP(880,448) → 窗口 (720,188)，与理论值完全一致。

### 验证

| 项 | 结果 |
|---|---|
| 松手落点 | ✅ 与 `光标 − 锚点` 完全一致（(760,220)、(720,188) 两次） |
| 松手后移开鼠标 | ✅ 窗口不动 |
| 单击后移开鼠标 | ✅ 窗口不动 |
