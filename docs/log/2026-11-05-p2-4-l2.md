# 2026-11-05 · P2-4 L2 自动动画

## 目标

用户只给**一张立绘**，程序自动做出呼吸、点击弹跳、拖拽倾斜、睡觉的呼吸——
不需要画 12 帧雪碧图。

这是降低门槛的关键：L3 要求用户画 20 帧（美术都要画半天），L2 只要一张图。

## 完成内容

### 1. 校验器 `importSingleImage()`

比 L3 宽松得多：

| 检查 | 要求 | 错误提示 |
|---|---|---|
| 能读取 | PNG | 「文件读不出来」 |
| 比例 | 0.7–1.4（接近正方形） | 「横躺或竖长的人物会被拉伸」 |
| 边长 | 128–1024 | 「太小 / 太大」 |
| 透明 | ≥15% 像素带 alpha | 「看起来是白底，请导出带 Alpha 的 PNG」 |

生成的包是 `columns:1, rows:1`，`PetView` 据此判断走静态动画分支。

### 2. 三种动画（`renderStatic`）

| 动作 | 实现 | 周期 |
|---|---|---|
| 待机 | `scale(1±0.012, 1±0.022)` 正弦 | 3.2s |
| 点击 | `translateY(-10px)` + 挤压回弹 | 0.42s 后回调 |
| 拖拽 | `rotate(±4deg)` 摆动 | 1.1s |
| 睡觉 | 缩小 + 更慢的呼吸 + 透明度 0.94 | 4s |

### 3. 导入入口

托盘「我的角色」下现在有两个：

```
导入立绘（单张，自动动画）…   ← L2
导入雪碧图（多帧）…          ← L3
```

## 关键发现：CSS 动画在透明窗口上贵得离谱

第一版用 CSS `@keyframes` 做动画，测得：

| 方案 | 空闲 CPU | GPU |
|---|---|---|
| CSS 关键帧 + `drop-shadow` 滤镜 | **42.7%** | 35% |
| CSS 关键帧（去掉滤镜） | 24.8% | 20.9% |
| **JS 驱动 8fps（最终）** | **5.16%** | 2.2% |
| 雪碧图 6fps（L3，对照） | 5.89% | 1.6% |

两个原因，都很反直觉：

1. **`filter: drop-shadow` 在元素每帧 transform 时会强制重新栅格化**，
   完全破坏了合成器优化。去掉就少一半。
2. **CSS 动画跑 60fps**，而这窗口是透明 + 置顶的，每帧合成都要走完整流程。
   改成和雪碧图同频的 8fps JS 驱动，开销立刻回到一个量级。

> 教训：「用 transform 就便宜」只在**不叠加滤镜**、**不跑满 60fps** 时成立。
> 透明窗口的合成成本比普通窗口高，帧率是第一杠杆。

顺带说明：**L2 现在比 L3 还省**（5.16% vs 5.89%），因为不用改 background-position。

## 遗留

- **没有眨眼**：需要用户额外给一张「闭眼差分图」，可作为 L2.5
- 睡觉只有缩放，没有 zzz 特效
- 拖拽倾斜幅度固定 ±4°，不随拖动速度变化
