# 2026-11-09 · P3-5 桌面启动入口（本地稳定安装）

## 背景

之前每次要看桌宠，都得有人在命令行里启动 `electron.exe .` / `pnpm start`。
用户桌面上 48 个快捷方式，没有芯宠。

## 方案（三选一，选了 A）

| 方案 | 做法 | 结论 |
|---|---|---|
| **A. 快捷方式 → 打包版** | 打包产物放到仓库外的固定目录，桌面 + 开始菜单建快捷方式 | ✅ 本次做 |
| B. 快捷方式 → 开发构建 | 指向 `node_modules/electron/dist/electron.exe`，每次改完要 `pnpm build` | ❌ 不是用户形态 |
| C. NSIS 安装包 | `electron-builder` 加 nsis target，装完自动建快捷方式/卸载项 | 📋 排成 P3-6，答辩前做 |

选 A 的理由：**打包版才是用户最终拿到的东西**（无控制台、日志写 `%APPDATA%\xinchong\main.log`），
开发版调试时行为不一样（`pnpm dev` 甚至不产出 `out/renderer`）。

## 做了什么

1. 打包产物（`dist\win-unpacked`，310MB）复制到 **`E:\XinChongApp`** —— 仓库外、不会被 `build:win` 清掉。
2. 建两个快捷方式，都指向 `E:\XinChongApp\XinChong.exe`：
   - `C:\Users\lenovo\Desktop\芯宠.lnk`
   - `%APPDATA%\Microsoft\Windows\Start Menu\Programs\芯宠.lnk`
3. 通过桌面快捷方式实际启动验证：进程起来、桌宠出现在右下角、`main.log` 正常写入。

## 两个坑（记下来）

### 1. 从带 `ELECTRON_RUN_AS_NODE=1` 的终端启动会静默退出

现象：双击（或从我这个 shell）启动 `XinChong.exe` 立刻退出，无日志、无报错。
原因：当前终端继承了 `ELECTRON_RUN_AS_NODE=1`（DSH 环境自带），Electron 会以 **Node 模式** 跑这个 exe，
遇到 `--enable-logging` 之类的参数直接报 `bad option` 退出。

排查时差点误判成"打包版坏了"。**验证打包版一定要先 `Remove-Item Env:ELECTRON_RUN_AS_NODE`**。
用户从桌面双击（Explorer 启动）不受影响——那里没有这个环境变量。

### 2. 别把安装产物拷进仓库或仓库克隆

第一次我把 `win-unpacked` 拷进了 `E:\XinChong`（那是一个仓库克隆），
结果 Electron 的一堆 dll/pak 散落在仓库根目录。已用 `git clean -fd` + 删 `XinChong.exe` 还原干净。
安装目录必须在仓库外、英文路径。
