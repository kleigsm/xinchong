# 2026-11-22 · P1-13 隐私设置页

## 目标

老师反馈「隐私设置部分做的不太完善」。现状是：隐私说明散落在「聊天」「关于」两个页面里，
而且全是纯文案——用户看得到，但**核对不了，也删不掉**。

这次做一个独立的「隐私」分区，把「存了什么 / 什么时候出网 / 怎么删掉」变成可操作、可核对的东西。

## 完成内容

### 1. 新增「隐私」分区（导航第 8 项）

设置面板从 9 项变 10 项：角色 / 性格 / 外观 / 声音 / 行为 / 聊天 / 系统 / **隐私** / 怎么玩 / 关于。

页面由五张卡片组成：

| 卡片 | 内容 |
|---|---|
| 一句话 | 承诺 + 四个状态徽章（图片不上传 / 聊天默认关闭 / 无账号无遥测 / 完全离线或可能出网）+ 出网说明 |
| 本机数据清单 | **实时扫描**出来的每一项：是什么、相对路径、多大、行内「清除」按钮 |
| 聊天时会发送什么 | 「会发送 / 不会发送」两栏对照，含「最近 3 轮对话只在内存」和「测试连接会发一个 ping」 |
| 运行日志 | `privacyLogs` 开关（默认开），关掉后不再写文件 |
| 清除数据 | 「全部清除并恢复出厂」（双重确认）+ 清除结果回显 |
| 我们的承诺 | 数据最小化 / 本地优先 / 加密存储 / 可撤回 / 可审计 |

### 2. 清单来自真实文件系统（`src/main/privacy.ts` 新建）

- `collectPrivacyReport()`：每次调用都重新扫 `userData`，返回 settings.json / pets/ / chat-key.bin /
  main.log / 其它运行时文件这五项的存在、字节数、文件数。
- `clearPrivacyData(target)`：`chat-key` / `pets` / `logs` / `all`。`all` 会删角色、删 Key、删日志、
  并把 settings.json 整个删掉（回默认值），同时把 `activePetId` 置空并通知桌宠换回内置角色。
- 「删完数字会变小」是这一页的核心承诺，所以清除后前端会重新拉一次报告再显示结果。

### 3. 运行日志开关

- `Settings` 新增 `privacyLogs: boolean`（默认 true）
- `main/index.ts` 里的 `setupLogging()` 抽到 `src/main/logging.ts`，新增 `setLogWriteEnabled()`
- `api:settings:patch` 收到 `privacyLogs` 时立即生效，不用重启
- 关掉只是不再追加，已有 main.log 要手动「清除」

### 4. 隐私文案去重

「聊天」页和「关于」页原来各有一大段隐私说明（内容已经开始不一致），现在收敛成一行 + 「打开隐私页」按钮。

## 踩的坑

1. **递归扫 `userData` 把主进程卡死（第一版）**。连同 Electron 的 `Cache/` `GPUCache/` 一起数，
   真实机器上几万个文件 + 同步 `fs`，结果设置窗口不响应，连调试端口都超时。
   现在：只精算用户数据（pets 目录上限 2000 个文件），缓存目录**只数顶层条目、不统计大小**。
   这条正好撞产品红线「不能卡顿」，所以写进了注释。
2. **清除按钮重复**：清单行内有一套、底部卡片又有一套，`[data-target="logs"]` 一次命中 2 个元素。
   收掉底部的单项按钮，只保留「全部清除」；单项清除就在数据行上。
3. **路径两种写法混用**：表头写绝对路径、行内写 `%APPDATA%\xinchong\...`，看着像两个位置。
   统一成「表头给一次完整路径，行内只给相对名」。

## 遗留

- **卸载自动清数据仍没有钩子**：现在靠设置页「清除」。要做实得等 P3-6 的 NSIS uninstaller。
- 运行时缓存不统计也不删（运行中删不安全），页面已写明「退出后手删 `%APPDATA%\xinchong`」。
- 日志开关目前只在开发版验证了逻辑；打包版（`app.isPackaged` 为真）的写文件路径未实测。
