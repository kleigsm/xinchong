# 2026-11-04 · 拖动漂移修复

## 现象

用户实测：球能拖动，但**位移与鼠标逐渐产生偏差**（越拖越偏）。

## 原因

原实现用渲染层传来的 `event.screenX / screenY` 计算位置：

```
renderer(screenX) --IPC--> main(setPosition)
```

在 **125% 缩放**的屏幕上，渲染层的屏幕坐标单位与 `win.setPosition` 使用的 DIP 坐标系不一致，
导致每次移动都被放大/缩小一个比例，误差逐步累积。

## 修复

改成**主进程完全接管拖动**，不再使用渲染层坐标：

- `drag-start`：用 `screen.getCursorScreenPoint()` 记录 `偏移 = 光标 - 窗口位置`
- 按住期间：每 **16ms** 读一次系统光标，`窗口位置 = 光标 - 偏移`
- `drag-end`：停止定时器并做边界钳制

`screen.getCursorScreenPoint()` 与 `win.setPosition()` 同为 DIP，**与缩放无关**。

## 附带收益

原来鼠标拖出 220×220 的小窗口后会收不到 `mousemove`，宠物会"卡住"；
现在主进程独立跟随光标，**鼠标移出窗口也不会掉队**。

## 验证

```
[drag] start cursor=(1307,547) window=(1196,436) offset=(111,111)
[drag] end, window at (876,196)
```

鼠标物理位移 −400/−300（DIP −320/−240），窗口终点
`876 = (1307−320) − 111`、`196 = (547−240) − 111`，**误差 0**。

另测：拖动过程中鼠标移出窗口范围再松开，`drag end` 正常触发，窗口停在期望位置。

## 遗留

- 仍保留 `drag-move` IPC 通道（空实现）以兼容旧调用，P1-1 重构时可删除。
