# 2026-11-06 · 聊天修复：第二次打不了字 + 回复质量

用户反馈两个问题：

1. 填了 Key，但它说的话"不太准"
2. **只有第一次能输入，后面点输入框打不进字**

---

## 一、第二次打不了字（真 bug）

### 原因

桌宠窗口是 `focusable: false`（为了不抢焦点），聊天时临时改成可聚焦：

```ts
win.setFocusable(true);
win.focus();
win.webContents.send("pet:chat-input");   // ← 立刻发
```

**问题在于时序**：`win.focus()` 之后窗口还没真正拿到键盘焦点，事件就已经发到渲染层了，
渲染层执行 `input.focus()` 时落空——第一次碰巧能成（窗口刚显示时系统会给焦点），
第二次就失效了。

### 修复

主进程：

```ts
win.setFocusable(true);
win.show();
win.focus();
win.webContents.focus();        // ← 关键：webContents 也要拿焦点
setTimeout(() => send("pet:chat-input"), 60);   // ← 延迟，等窗口真正激活
```

渲染层：

```ts
requestAnimationFrame(() => chatInput.focus());
setTimeout(() => { chatInput.focus(); chatInput.select(); }, 120);
```

另外给输入框外层加了 `mousedown → focus()`，点一下就能重新聚焦。

### 验证

加了个开发钩子 `XINCHONG_CHAT_INPUT=twice`（第 2 秒、第 12 秒各弹一次输入条）。
第二次弹出后直接打字 → 输入框里成功出现「第二次也可以」。

## 二、回复"不太准"

### 只改了几处，但都是关键

| 项 | 之前 | 现在 |
|---|---|---|
| 上下文 | **没有**，每句都是单轮 | 带最近 3 轮对话（内存里，不落盘） |
| 人设 | 一句话形容词 | 性格描述 + **两个示例对话** |
| 温度 | 0.9（偏飘） | 0.7 |
| max_tokens | 60 | 80（防止话被截断） |
| 规则 | 3 条 | 5 条（含"不知道就说不知道，不要编"） |

### 为什么要加示例

只写"你是一只害羞的桌宠"，模型容易回成百科全书式的解释。
给两个示例（`用户：在吗 → 在、在的……怎么啦`）比任何形容词都管用。

### 为什么要加历史

之前每一句都是独立请求，所以它会"失忆"——
你说"我叫小明"，下一句问"我叫啥"它不知道。现在带最近 3 轮。

### 还清空了换人设的上下文

`resetChatHistory()` 导出备用，避免换性格后还带着上一种性格的对话记忆。
