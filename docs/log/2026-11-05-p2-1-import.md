# 2026-11-05 · P2-1 第一刀：导入角色的垂直切片

## 目标

不做完整 UI，先把**「选文件 → 校验 → 存盘 → 立刻换上」**这条链路打通，
用美术的真图验证一遍。

## 完成内容

### 1. 用户素材存储层 `src/main/pet-store.ts`

```
%APPDATA%\xinchong\pets\
  <id>\
    pack.json     ← 角色包（sprite.image 存 "sprite.png" 相对名）
    sprite.png    ← 雪碧图
```

放在 userData 而不是程序目录：重装不丢、不需要管理员权限。
`pack.json` 里存相对文件名而不是绝对路径——换机器、换用户名都能用。

id 做 sanitize（只允许小写字母/数字/连字符，≤32），并校验防目录穿越。

### 2. 校验器 `src/main/importer.ts`

**不用 sharp**：Electron 自带 `nativeImage` 就能读尺寸、`toBitmap()` 能扫 alpha，
省掉一个原生依赖（在这个网速下装 sharp 本身就是风险）。

校验顺序：

| 检查 | 错误提示（人话） |
|---|---|
| 能否读取 | 「文件读不出来，请确认是 PNG」 |
| 宽能被 4 整除 | 「宽度 600 不能被 4 整除」 |
| 高是格高的整数倍 | 「高度不是每格高度的整数倍」 |
| 正好 4 行 | 「图片有 3 行，但需要 4 行」 |
| 格子在 64–256 之间 | 「每格 512，超出允许范围」 |
| 有透明区域 | 「几乎没有透明区域，导出时请勾选透明背景」 |
| 四个必需动作首帧非空 | 「第 8 格（拖拽）是空的」 |

非致命问题只警告（比如第 10/11 格有内容但当前配置用不到）。

### 3. 导入流程 `src/main/import-flow.ts`

两个入口：

- `runImportFlow()`：弹文件对话框，给用户用
- `importFromPath()`：直接按路径，给自动化测试用

### 4. 立即换上

主进程把雪碧图转成 data URL，通过 `pet:use` 发给渲染层。
渲染层收到后换角色包、重建台词库、回到待机、冒一句「换上了「xxx」」。

用 `usingUserPet` 标记：一旦用上用户角色，就不再跟随「性格」设置切换。

### 5. 托盘菜单

新增「导入角色…」。

## 过程中抓到两个真 bug

### ① CSP 挡住了 data URL

导入后宠物**整个消失**。原因是 `index.html` 的 CSP：

```
default-src 'self'    ← data: 图片被拦
```

浏览器控制台会报 `Refused to load the image`，但用户只看到"宠物没了"。

**修复**：加 `img-src 'self' data:`。

### ② 事件发得太早

第一版在 `did-finish-load` 时立刻发 `pet:use`，
但渲染层的 `onUsePet` 订阅可能还没执行完——事件直接丢了。

**修复**：渲染层初始化完成后主动发 `renderer-ready`，主进程收到再派发。

> 这类"主进程太急"的时序问题，在有 IPC 的桌面应用里非常常见。
> 规矩：**主进程永远不要假设渲染层已经准备好了**。
