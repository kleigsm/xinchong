## 三个设计决定

### 1. 长按和摸头串联，不并列

摸头已经是长按 1.2s。浮球放在 **2.0s**，让摸头（0.67s 动画）先播完再弹菜单：

```
按下 ─1.2s→ 摸头 ─2.0s→ 浮球
松手在 1.2~2.0s 之间 → 只有摸头
```

用户学到的规则是「按得越久，给的越多」，摸头还顺带成了"菜单正在蓄力"的反馈。

### 2. 浮球是快捷方式，不是替代

右键菜单**保留**，只做信息架构改版（三组 + 图标 + 快捷键）。
原因：Windows 用户对右键有肌肉记忆；浮球解决的是"新用户不知道有右键"。

### 3. 命中区域要抽象出来，不能再逐项写死

输入条那个 bug（11-08）的根因是：新 UI 元素忘了加进 `hit-test.ts`。
浮球有 4 个圆，再写死 if 就是 bug 复刻。规范里给了 `interactive-regions` IPC 方案：
渲染层把当前可交互区域推给主进程，命中检测只做并集判断。

## 实现约束（写进规范了）

- 动画只允许 `transform` / `opacity`；**禁止** `filter`（perf-baseline 第八节：drop-shadow 让 CPU 6% → 42.7%）
- 浮球静止后零动画；菜单打开时空闲 CPU < 8%
- 同一时刻只能有一个面板（浮球 / 输入条 / 右键菜单互斥）
- 浮球只由长按触发，5 秒无操作自动收回（守住"不主动打扰"）

## 原型里踩到的两个坑（写下来免得实现时再踩）

1. **Image 预加载对象被 GC 掉**：`const probe = new Image()` 局部变量，onload/onerror 可能永远不触发，表现为"图不显示也不报错"。要保留引用。
2. **长按松手不该关菜单**：原型第一版里 pointerup 会把刚弹出的菜单关掉。要用 `openedByThisPress` 标记区分"长按弹出"和"点击收起"。
